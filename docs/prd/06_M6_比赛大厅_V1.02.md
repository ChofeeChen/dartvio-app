### 15.5.1 v0.1.13 联机房间退出治理（真机反馈驱动）

任一方（房主或客人）退出后，房间**继续存活 30 秒**（`ABANDON_GRACE_MS`）：误触返回还能点回来接着打；到期后才置「已结束」并**从大厅列表移除**。修复前的表现：房主返回留下「已结束」同名卡、客人退出留下「等候中 1/2 人」死房间（点进去只有回合记录、没有任何下一步）。对局页返回（**含系统返回键**——此前只有顶栏箭头会通知服务端）现在真的会 `leaveRoom`；大厅列表新增「`status == ENDED` 不进列表」过滤。

### 15.5.2 v0.1.14 分清「房间名 / 玩家昵称 / 实力」三件事（真机反馈驱动）

- **昵称只有一份真源**：删除 `PlayerProfileStore` 自存的昵称 / 头像副本（死代码 + 第二真源）。此前「我的」页改昵称只写档案、房间仍读旧副本 → 同一个人在自己手机上显示「玩家xxxx」、在别人手机上是「茄子」。现在房间侧只读档案，「我的」页保存后统一 `hydrateLocalUser` 同步 name + avatar。
- **大厅房间卡加「房主：昵称」**（此前只有房间名 + PPR，陌生人只能从「茄子的房间1」里猜是谁开的）；等候页顶栏把「这一局叫什么」与「谁开的」分成两行，不再互相顶替。
- **PPR 打通到每个人**：加入者的 PPR 随 `member_joined` 事件下发（`ppr` 默认 0 兼容老端，**0 读成「没有」、不显示 0.0**，避免被读成「他很菜」）；房主那份沿用索引行 `host_ppr`；等候页成员行与对局页玩家卡（X01 转播惯例：已赢局数 + PPR）都显示。

## 1. 问题陈述

当前「在线对战」入口后的流程是 V1.01 的整页表单 + 房间号加入 + 平铺混合列表：等待房与进行中对局混排在同一列表，用户进大厅后要先靠文字分辨「这局能不能打」，再去找创建入口；房间号输入与分享把「找对手」变成了一个需要双方线下沟通的动作。三款竞品的共同解法是：把「开一局」和「看一局」分成两条明确路径，卡片右上角用动作按钮直接表达意图，创建收进一层弹窗。DartVio 需要同等清晰度，才能把「大厅浏览 → 进房开打」的转化做起来。

**不解决的代价**：大厅停留后流失、房间号沟通失败导致的空房堆积（无人加入也永不消失）、观战入口无人发现。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G1 | 进大厅后 3 秒内看清「可加入 / 可观战」两类机会 | 双 Tab 分区 + 卡片动作按钮 |
| G2 | 从进大厅到进对局的路径不超过 3 次点击 | 创建/加入均 ≤ 2 次点击 + 1 次确认 |
| G3 | 空房不再长期占位 | 公开等待房 5 分钟无人加入自动销毁 |
| G4 | 联机链路零回归 | v0.1.10 蜂窝联机成功率不下降、对局页零改动 |

### 2.2 非目标（本期明确不做）

| 非目标 | 原因 |
| --- | --- |
| 国旗、信用分 / Pro 门槛标签 | 与 DartVio 当前用户体系无关，竞品特性不照搬 |
| 3–4 人房间 | 现有 RoomStateCodec 快照为 host/guest 双人结构，多人民房需改协议 |
| 私密房 / 房间密码 / 房间号加入 | 决策 D5：所有房间公开列出，凭卡片直接加入 |
| 真实在线人数 presence、Lv、PPR、观战人数 | 现有引擎无对应数据，P1 随统计系统一起做 |
| 局域网 / WiFi 直连（含全部入口与代码） | 决策 D1：联机只要求手机连互联网 |
| 对局页与观战页 UI 改造 | 保持现有设计，本次只改入口来源 |
| 视频观战、靶盘动画观战 | P2 预留 |

## 3. 决策记录（已确认，不可回退）

| 编号 | 决策 | 结论 |
| --- | --- | --- |
| D1 | 联机形态 | 只保留云端（Supabase）一条路。移除局域网/WiFi 直连的全部界面入口与代码；比赛大厅联网只要求手机连接互联网，不判断是否在同一局域网 |
| D2 | 重构策略 | 新 UI、旧引擎。界面按本文档重写；数据层全部映射到现有 Supabase 事件溯源引擎（dartvio_room_events 事件表 + 3 秒 REST 轮询兜底 + Realtime WS 推送，v0.1.10 蜂窝握手修复）保持不变 |
| D3 | 创建房间形态 | 底部 BottomSheet + 「高级规则设置」折叠区；⋮ 三点入口查看规则 |
| D4 | 空房过期 | 公开等待房创建后 5 分钟无人加入 → 自动销毁；卡片可见倒计时 |
| D5 | 加入方式与人数 | 去除房间号/密码/私密房；房间固定 2 人上限，满员关闭加入 |
| D6 | 卡片字段 | P0：头像、昵称、在线点；不做 Lv / PPR / 国旗 / 信用分 / 观战人数（均为 P1 或永久不做） |
| D7 | 观战入口 | 参照 Dartsmind：卡片右上角眼睛图标 + LIVE 角标，仅对进行中对局开放；整卡可点进入观战 |
| D8 | 满员等待房 | 不提供观战按钮，只显示「房间已满 · 等待开始」 |
| D9 | 删除房间 | 唯一入口收在房间等候页 P4；大厅置顶卡不提供删除按钮 |
| D10 | 一人一房 | 不允许同一用户同时处于多个未结束房间；创建/加入前命中既有房间则引导回该房 |
| D11 | 创建入口 | 唯一：右下角 FAB；空状态不重复放按钮，仅文案引导 |
| D12 | 顶栏在线人数 | P0 显示「等待 N · 对局 M」（两个列表计数）；真实在线人数 presence 为 P1 |

## 7. 用户故事

### P0 主路径

- 作为想立刻打一局的用户，我希望进大厅就看到可加入的等待房，点一下就进房，不要输房间号。
- Given 大厅有 1/2 等待房 / When 我点 [加入] / Then 直接进入等候页且我已自动准备。

## 10. 房间生命周期状态机

(无) ──createRoom()──▶ waiting(1/2) ← 记录 expiresAt = now + 5min

waiting(1/2) ──player_joined──▶ waiting(2/2) ← 满员：关闭加入，expiresAt 置 null

waiting(1/2) ──creator_left / 解散──▶ destroyed

waiting(1/2) ──now >= expiresAt──▶ destroyed（★ 自动过期，发 room_destroyed）

waiting(2/2) ──all_ready + start()──▶ playing

waiting(2/2) ──player_left──▶ waiting(1/2) ← 回到 1/2，重新计 5 分钟

playing ──leg_finished──▶ playing

playing ──match_finished──▶ match_finished（结果可见）──▶ destroyed

playing ──player_offline > 60s──▶ match_finished（判负）──▶ destroyed

要点：2 人固定上限；仅 1/2 房计时；判负先落 match_finished 再销毁，保证观战台能看到结果。

- **① 缺列会让整组元数据一起降级（已修）**：建房时 join_policy / host_name 两列当时还没加进库，PostgREST 回 PGRST204，而原逻辑是「整组降级」—— 连带把已经加好的 host_avatar / expires_at 一起不写。症状是「建房显示成功，但大厅没有房主头像、等待房永不过期」，且无从察觉。已改为**逐列探测、逐列降级**（OnlineRoomApi.supportedMetaColumns()）：缺哪列只丢哪列；诊断现在会直接列出「已有 / 缺失」的列。
- **② 大厅会被无人认领的房间塞满（未解决，见 Q8）**：房间行只有 SELECT / INSERT 策略，anon **不能 DELETE** —— DELETE 返回 204 但影响 0 行。诊断与联调留下的 30 多行测试房（「联调测试房」/「诊断测试房」）全部堆在大厅，而这些房的 expires_at 为 null，过期清理任务也不会碰它们。（2026-09-25 已一次性清理：`dartvio_rooms` 归零）。

| 当前状态 | 事件 | 下一状态 | 触发者 | 说明 |

| playing | leg_finished | playing | 系统 | 一局结束，自动开始下一局 |
| playing | match_finished | destroyed | 系统 | 比赛结束，房间自动销毁 |
