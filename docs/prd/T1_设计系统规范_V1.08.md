## 0.1 可替换主题 Token 架构

D-THEME-001 \| CONFIRMED \| 2026-09-15 \| 用户正式认可；A 类工程可逆优化。采用可替换主题 Token 架构，不锁定最终 UI 风格或品牌色。本次仅修订文档，不创建主题代码。

统一入口 DartVioTheme 基于 Material 3 ColorScheme；页面和可复用组件仅消费 MaterialTheme.colorScheme 或 DartVioTheme 的语义扩展。原始调色板、状态色及明暗映射集中于主题层，替换色板不得逐页修改。

禁止页面硬编码颜色：不得直接使用 Color(十六进制/通道值)、Color.Red/White/Black 等固定色、parseColor、页面私有调色板、写死的渐变或着色资源绕过主题。纯透明绘制等如确需例外，只能经集中 Token/规则明确处理，不能由页面自行豁免。原始色值只允许在明确限定的主题映射/调色板层定义。

语义颜色契约：主色 primary/onPrimary/primaryContainer/onPrimaryContainer；辅助色 secondary/onSecondary/secondaryContainer/onSecondaryContainer；背景 background/onBackground；容器 surface/onSurface/surfaceVariant/onSurfaceVariant；文字 textPrimary/textSecondary/textDisabled；边框 border/borderSubtle；错误 error/onError/errorContainer/onErrorContainer；警告 warning/onWarning/warningContainer/onWarningContainer；成功 success/onSuccess/successContainer/onSuccessContainer。名称表示语义角色，不是最终色值。

映射约定：Material 3 已有角色由 ColorScheme 提供，文字/边框等语义别名集中映射至相应 on*、outline 等角色；warning 与 success 等补充角色由 DartVio 扩展 Tokens 集中提供，并随主题统一注入。业务代码不得另建零散状态色常量。最终 API 字段适配实际依赖版本，不在文档中锁定库版本。

明暗结构：建立 Light 与 Dark 两套相同语义结构，状态色、容器色及其前景色均成对定义。浅色是当前验收主题，预览与验收入口显式指定 Light；Dark 验证结构完整及内容可读。最终品牌色、渐变、插画及 UI 风格仍为 OPEN。原橙/青/金及固定深色数值仅为历史候选，不作为最终品牌验收条件。

修订说明：下段配色/默认主题口径已由§0.4替代；非颜色要求及其他OPEN继续有效。

动态取色：默认关闭，不根据壁纸自动替换 ColorScheme；是否向用户开放、入口及策略为 OPEN，须后续产品决定。浅色验收配置不等于裁决产品运行时默认主题，旧“深色基调”与“跟随系统”之差异仍不得擅自选定。

非颜色 Token：字体族/字重/字号/行高采用 Typography Tokens；间距采用 Spacing Tokens；圆角采用 Shape Tokens；图标/控件/热区尺寸采用 Size Tokens；阴影/层级采用 Shadow/Elevation Tokens。布局单位 dp、字号 sp。Token 化要求已确认，最终数值、字体资源与视觉风格仍为 OPEN；旧尺寸仅作候选参考，不机械固化。

状态表达：错误、警告、成功、连接状态、选中与禁用状态不能只靠颜色；须配合文字、图标、形状或其他可感知标记，并提供可访问语义。改变主题不得改变状态含义。

# 1. 设计原则

DartVio 的设计遵循以下核心原则，所有视觉和交互决策都应以此为判断标准。

| 原则 | 说明 | 正反例 |
| --- | --- | --- |
| 精准 | 飞镖运动的核心是精准，UI 元素对齐精确、数据展示准确、反馈及时 | 正：比分数字精确到个位；反：模糊的"大约30分" |
| 专注 | 对局中不干扰用户投镖，非关键信息弱化，关键信息突出 | 正：对局页大比分+靶盘，次要信息折叠；反：对局中弹出广告 |
| 一致 | 相同功能在不同页面使用相同组件和交互模式 | 正：所有确认按钮都是主色圆角按钮；反：A页绿色确认，B页蓝色确认 |
| 高效 | 减少操作步骤，常用功能一键可达 | 正：快捷按钮一键输入常用分数；反：每次都要逐位输入60分 |
| 可访问 | 支持深色模式、大字号、足够触控热区、高对比度 | 正：最小触控热区44×44pt；反：按钮文字小到看不清 |
| 克制 | 不滥用动效和颜色，信息层级清晰 | 正：仅Checkout/180/胜利有庆祝动画；反：每个操作都有弹跳动画 |

# 9. 动效系统

## 9.1 动效原则

- • 动效服务于功能，不为动而动
- • 时长≤300ms（除庆祝动画），不阻塞用户操作
- • 使用自然缓动（ease-in-out / spring），避免线性运动
- • 可在设置中关闭"减少动效"（辅助功能）

THEME-01 集中式主题：检查 DartVioTheme、ColorScheme 与扩展 Tokens；通过标准：页面只消费语义 Token；替换调色板不需要逐页修改。

| G4 | **同行按钮等宽同高**：`weight(1f)` + `height(52.dp)`，主次只靠颜色分 | 同一行出现高度差或宽度差 | 高度差会被读成「上面那个更重要」 |
| G5 | **主数字 ≤ 56sp，结果页标题 ≤ 20sp** | 结果页出现 ≥ 60sp 的数字 | 60sp 及以上只留给计时 / 对局主比分 |
| G6 | **同类卡片四件套一致**：圆角 16dp / 内边距 16dp / 底色 Surface / 边框 1dp Divider；**卡距 12dp、段距 20dp** | 同一列里出现两种圆角或两种底色 | 「我的」页反馈 2026-09-27 |
| G7 | **键盘 / 输入区必须有界高度且常驻**：切换回合只改 `enabled`，不得隐藏或重建 | 版面高度随状态跳位 | 见 §8.15；对局页五段布局 2026-09-27 |

## 14.2 结果页骨架（唯一写法）

```
Column(fillMaxSize().background(Background).navigationBarsPadding().padding(16.dp)) {
    Column(weight(1f).verticalScroll(rememberScrollState()), spacedBy(16.dp), align = Center) {
        // 标题 20sp → 成就卡 → 主数字（≤56sp）→ 指标行 → 明细表
    }
    Spacer(height(12.dp))
    Row(fillMaxWidth(), spacedBy(12.dp)) {
        Button(weight(1f).height(52.dp)) { "返回" }     // 中性色
        Button(weight(1f).height(52.dp)) { "再来一次" } // 主色
    }
}
```

两条理由，分别对应两个真实的坑：

- **内容区自己滚动，按钮不跟着滚** —— 结果页的出口必须在任何数据长度下都不需要「找」；
  把按钮放进滚动区，短内容时它在半空中，长内容时它在屏幕外。
- **按钮单独放在滚区之下** —— 它是这一页的出口，不是这一页的内容。
