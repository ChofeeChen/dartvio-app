# 1. 模块概述

M9 统计成就模块负责个人统计数据计算与展示、比赛历史、成就系统、战绩分享。一句话原则：真人对真人的数据进排名，真人打的投镖数据进个人成长，练手的数据只留在本地。
★V1.00 口径基线（与 App V0.1 已实现代码对齐；本版所有公式以代码既有不变量为准，禁止另立口径）：
　• PPR = 总得分 ÷ 回合数，回合数 = 实际投镖数 ÷ 3，即 ppr = totalScored / (dartsThrown / 3.0)，与代码 X01PlayerState.ppr 一致；
　• Cricket 的 Mark / 得分 / 已关闭分区取自代码 CricketPlayerState，但 CricketMarks.marks 是「每局封顶 3 的当前状态」，不可求和当累计（见 §8.3.1 勘误）；
　• 三层可信度在 V1.00 的真实可用性：S级 仅「本地正式」可用（在线部分待 M5），A级「本地休闲 / vs DartBot」可用，B级「练习」待 M11 —— 即 V1.00 不产生在线数据，也不产生练习数据。

# 5. 数据质量与特殊边界处理（v1.1新增）

## 5.1 快速总分模式的数据粒度限制

快速总分模式（input_mode=quick_total）下，非Checkout回合的darts固定为"第1条=总分(label=TOTAL) + 第2/3条=MISS"。这意味着：

- • 每镖具体分区（T20/D16/S5等）不可知
- • 基于每镖的统计指标（T20命中率、三倍区占比、平均每镖得分分布、结镖路线分析）在此模式下不可用
- • Checkout回合通过M3弹窗记录checkoutDarts（1/2/3镖），可用于"结镖镖数分布"统计，但无具体结镖路线
M9实现要求：统计每镖维度指标时，必须过滤input_mode=quick_total的回合（Checkout回合的checkoutDarts除外）。在统计页标注"每镖维度统计仅包含逐镖录入模式的对局"。

## 5.2 含AI替补对局的数据拆分

在线对战中对手离线后AI替补的对局，数据需要按投镖者拆分：

- • 真人投镖的回合：计入该玩家的个人投镖统计（PPR/180/Bust率等）
- • AI投镖的回合：不计入任何玩家的个人统计，仅作为比赛记录保存
- • 比赛胜负：不计入胜率排名
- • 比赛记录标注"含AI替补"，并可展开查看哪些回合是AI投的
## 5.3 硬件自动计分数据的可信度标注

硬件自动计分（input_source=hardware_vision）是最高质量的数据源：

- • 在比赛记录和统计详情中标注"硬件认证"图标
- • 可设独立的"硬件认证数据"筛选器，用户可选择只看硬件计分的对局
- • 未来排行榜可设"硬件认证榜"，数据可信度最高
## 5.4 IN规则对第一镖数据的影响

Double In/Master In比赛中，第一镖不符合IN规则时该镖score=0（不是Bust，继续投下一镖）。M9统计时：

- • PPR计算：该镖按0分计入（符合实际），不特殊处理
- • 第一镖命中率统计：应区分"IN规则未命中（0分但允许继续）"和"正常MISS（0分）"，建议IN规则比赛的第一镖数据单独标注
- • Bust率：IN规则未命中不是Bust，不计入Bust统计
## 5.5 手机视觉计分数据的可信度标注（V1.03 新增）

手机视觉计分（input_source=phone_vision，模块 M12）为中等质量数据源：

- • 在比赛记录与统计详情中标注「手机视觉（半自动）」标签，与「硬件认证」图标严格区分
- • 不得标注「硬件认证」，不进入「硬件认证数据」筛选器与「硬件认证榜」
- • 因 M12 为半自动（需用户确认 / 修正），单镖数据存在人工修正成分；每镖维度统计默认包含，但支持按来源过滤
- • 数据来源说明（§6.1 的 ⓘ）需明确：phone_vision 数据由手机摄像头识别 + 用户确认产生，非硬件认证
# 6. 用户体验规范（v1.1新增）

## 6.1 数据来源必须可见、可解释

- • 每条统计指标旁加"ⓘ"图标，点击显示数据来源说明，如"此数据包含在线对战和本地正式赛，不含AI对战和练习模式"

排行榜顶部写清楚："仅统计在线真人对战和本地正式赛（玩家2登录），本地正式赛权重0.8，AI对战和练习模式不参与排名"。这一句话能避免90%的用户投诉。

## 6.3 AI对战数据单独成体系

- • （v1.4调整）不再设独立"DartBot挑战"页面：AI难度唯一来源为M4四档（入门/进阶/高手/专业，PPR25-90），AI对战数据并入个人统计（标注"含AI对战"），AI挑战成就作为非排名类成就保留
- • 设独立的AI成就："首次击败Hard"、"对Pro单回合180"、"对Pro连胜5场"
- • 个人主页核心数据（PPR/胜率）可包含AI对战的投镖数据，但标注"含AI对战"，并提供"仅看真人对局"筛选开关
## 6.4 本地休闲赛数据不完全丢弃

- • 玩家1的个人投镖数据（PPR/180/Checkout率）计入个人综合统计
- • 比赛结果（胜负）不计入胜率排名
- • 比赛历史保留完整记录，用户可回看"那天和朋友打了什么"
- • 标注"本地休闲赛·数据仅用于个人成长，不参与排名"
## 6.5 提供数据筛选器

统计页顶部加筛选器，让用户自己选择看什么：

- • 全部数据 / 仅正式比赛（在线+本地正式）/ 仅在线 / 仅本地 / 仅AI对战 / 仅练习
- • 用户想知道"我真实水平怎么样"时选"仅正式比赛"
- • 用户想知道"我最近练得怎么样"时选"全部"
- • 筛选选择应持久化保存（记住用户上次的选择）

★V1.00 口径勘误与实现要求（与上表冲突时，以本段为准）：
　• C1 Mark率：分子 = 逐镖累加的获得 Mark 数（每镖 0-3）。命中未关闭分区 → 得该镖 mark 数；命中已关闭分区 → 只得分、不记 mark。⚠️禁止用 CricketMarks.marks（封顶 3 的状态）求和，须在 CricketPlayerState 新增累计计数器。
　• C3 三倍区命中率：原口径「命中三倍区镖数 / 瞄准三倍区镖数」在纯键盘录入下不可实现 —— 键盘只记录投镖结果，不记录瞄准意图。V1.00 改为「三倍区命中镖数 / 总镖数」，与 C4 共用分母 dartsThrown；「瞄准后命中率」降级为硬件视觉录入（M8）专属指标，V1.00 不实现、不展示。

　• C6 平均关闭回合数：仅对「本局成功关闭全部 7 个分区」的局计入均值；未关满的局不计入分母。
　• C7 得分效率：= 总得分 ÷ 总镖数，与代码 CricketPlayerState.score 口径一致。
　• C9 最高单回合得分：代码仅有 lastTurnScore（上一回合得分），需新增 maxTurnScore，在每次回合结算后取 max 更新。

| A9.31 | 提示分栏 | 辅助成绩与无提示成绩分别聚合，辅助成绩不刷新无提示最佳 |
| A9.32 | 分母口径 | SKIPPED与ABORTED不进入成功率分母，重试单独记attempt |

# **12. 联机对局（source = LAN）的统计口径（★V1.08 新增）**

★口径：联机对局进「历史列表」，不计入 X01 统计指标 / 成就 / 排行榜。理由：①联机没有第三方裁判，比分自证；②联机存在「对手掉线判负」的主动触发路径，一旦计入战绩，拔网线就成了提高胜率的最省事手段。口径可随后续决策调整，但必须在本文与代码同时改。

| 数据范围 | 是否计入 | 判据（代码级） | 界面表达 |
| --- | --- | --- | --- |
| 历史列表（看得到） | 计入 | MatchRepository.observeMatches() 返回全量，含 source = LAN | 历史行加「联机」标签 + 房间号；判负行加「对手掉线判负」 |
| X01 统计指标（胜率 / PPR / 结镖率等） | 不计入 | MatchStatsFilter.countsForStats(record) 为唯一判据；observeStatsMatches() 先按 DAO 谓词过滤 | 筛选器结果不含联机行；用户查不到「为什么少了」时应有说明文案 |
| 成就解锁与进度 | 不计入 | AchievementRepository 取数改用 observeStatsMatches()；refresh 时按 countsForStats 再兜一次 | 成就页不出现因联机局解锁的记录 |
| 排行榜 | 不计入 | 同 X01 统计口径；第二道闸 isFormal = false | 排行榜列表不含联机成绩 |
| 胜者展示 | 单独成列 | 房主端只有线上身份，拿不到客人档案 ID，故 winnerName 独立成列，不做 users 反查 | 历史行显示的是房间内的显示名 |

# **12.1 为什么不能靠「拆表」实现隔离**

• 与 versus_* 不同：联机对局必须在历史列表里出现，因此它落的是同一张 match_records，隔离只能收在一处判据上，不能靠「表不同所以查不到」。

• ★唯一判据是 MatchStatsFilter.countsForStats(record)；DAO 的 WHERE source <> "LAN" 只是性能前置，Repository 与成就取数再用同一判据兜一次 ⇒ 「哪个新入口忘了写谓词」的后果是慢一点，而不是数据算错。

• ★第二道闸 isFormal = false：即使有调用方绕开 Filter，联机行也不会被当作正式战绩。

• MatchSource 对未知取值宽容回落 LOCAL（不抛异常、不静默剔除），避免老数据与跨版本读取时出现「数据凭空消失」。

# **12.2 两个读取入口的分工**

• observeMatches()：历史口径，含联机，给历史列表用。

• observeStatsMatches()：战绩口径，排除联机，给统计计算 / 成就 / 排行榜用；统计页同时取两份并用 combine 合并。

• 「看得到」与「算得进」是两件事，UI 上必须让用户看明白：历史里能查到，但不进战绩。

# **12.3 验收要点**

• 打完一局联机 → 历史列表出现该局并带「联机」标签与房间号；统计页 / 成就 / 排行榜数字不变。

• ★T8 弃权判负落的那一行带「对手掉线判负」，同样不进战绩。

• 老数据不受影响：DB v10 → v11 是纯增量四列，默认值为 LOCAL / 空串 / 空串 / 0，不订正 UPDATE，统计分母不变。

• 同一场对局重复触发结束只落一行（去重在 recorder 内部），不得重复计数。
