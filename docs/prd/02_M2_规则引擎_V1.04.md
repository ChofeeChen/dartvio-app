# 1. 模块概述

M2 规则引擎模块负责飞镖比赛的规则裁定：X01和Cricket游戏规则、IN/OUT规则、Bust判定、Checkout判定、结镖路线推荐。v1.2补全了IN规则的判定逻辑（v1.0/v1.1中validateScore接收inMode参数但函数体内未使用）。

# 2. X01 规则

## 2.1 IN规则（v1.2补全判定逻辑）

IN规则决定比赛开始时第一镖的要求：

| IN规则 | 第一镖要求 | 不符合时处理 | 适用场景 |
| --- | --- | --- | --- |
| Straight In | 无要求，任意分区均可开始计分 | — | 休闲/新手 |
| Double In | 第一镖必须命中双倍区（D1-D20或Bull=50） | 该镖不计分（0分），继续投下一镖，不是Bust | 正式比赛 |
| Master In | 第一镖必须命中双倍区或三倍区（D/T） | 该镖不计分（0分），继续投下一镖，不是Bust | 高级比赛 |

重要说明：IN规则不符合时，该镖记0分但不影响后续镖，选手继续投剩余的镖。这不是Bust——Bust是OUT规则范畴（得分超过剩余分或最后一镖非双倍恰好降为0）。

## 2.2 IN规则判定伪代码（v1.2新增）

function validateInRule(dart, inMode, isFirstDartOfLeg):
 // 只在一局的第一镖时检查IN规则
 if not isFirstDartOfLeg:
 return { passed: true, score: dart.score }

 if inMode == "STRAIGHT_IN":
 return { passed: true, score: dart.score }

 if inMode == "DOUBLE_IN":
 // 第一镖必须命中双倍区（multiplier==2）
 // Bull(50)是双倍区(multiplier=2)，Outer(25)是单倍(multiplier=1)
 if dart.multiplier == 2:
 return { passed: true, score: dart.score }
 else:
 // 不符合：该镖不计分，继续投下一镖
 return { passed: false, score: 0, reason: "Double In要求第一镖命中双倍区" }

 if inMode == "MASTER_IN":
 // 第一镖必须命中双倍或三倍区（multiplier==2或3）
 if dart.multiplier in [2, 3]:
 return { passed: true, score: dart.score }
 else:
 return { passed: false, score: 0, reason: "Master In要求第一镖命中双倍或三倍区" }

// 在逐镖录入时的实时提示：
// M3录入第一镖时调用此函数，如果passed=false，在预览区显示红色提示
// "⚠ IN规则：第一镖需命中双倍区，此镖不计分"
// 该镖score=0，但选手可继续投下一镖（不是Bust）

## 2.3 OUT规则与Bust判定

| OUT规则 | 结镖要求 | Bust条件 |
| --- | --- | --- |
| Straight Out | 任意分区恰好降为0即可结镖 | 得分超过剩余分 |
| Double Out | 最后一镖必须命中双倍区恰好降为0 | ①得分超过剩余分；②最后一镖非双倍区但恰好降为0（如剩余40，S20+S20=40，最后一镖S20非双倍→Bust）；③剩余1分（无法用双倍结镖） |
| Master Out | 最后一镖必须命中双倍区或三倍区恰好降为0 | ①得分超过剩余分；②最后一镖非双倍/三倍区但恰好降为0；③剩余1分 |

## 2.4 Bust判定伪代码（v1.1已修正B3示例）

function isBust(remainingBefore, darts, outMode):
 totalScore = sum(d.score for d in darts)
 remainingAfter = remainingBefore - totalScore

 // Bust条件1：得分超过剩余分
 if remainingAfter < 0:
 return true

 // Bust条件2：恰好降为0但最后一镖不符合OUT规则
 if remainingAfter == 0:
 lastDart = darts[-1]
 if outMode == "DOUBLE_OUT":
 if lastDart.multiplier != 2:
 return true // B3示例：剩余40，S20+S20=40，最后一镖S20(multiplier=1)→Bust
 if outMode == "MASTER_OUT":
 if lastDart.multiplier not in [2, 3]:
 return true
 // Straight Out无此条件

 // Bust条件3：剩余1分（无法用双倍结镖，仅Double/Master Out）
 if remainingAfter == 1 and outMode in ["DOUBLE_OUT", "MASTER_OUT"]:
 return true

 return false

## 2.5 Checkout判定

function isCheckout(remainingBefore, darts, outMode):
 totalScore = sum(d.score for d in darts)
 remainingAfter = remainingBefore - totalScore

 if remainingAfter != 0:
 return false

 // 恰好降为0，检查最后一镖是否符合OUT规则
 lastDart = darts[-1]
 if outMode == "STRAIGHT_OUT":
 return true
 if outMode == "DOUBLE_OUT":
 return lastDart.multiplier == 2
 if outMode == "MASTER_OUT":
 return lastDart.multiplier in [2, 3]

 return false

★ 2.5.1 Checkout镖数可达性判定 isCheckoutReachable()（★v1.7新增）

快速总分模式下，系统不知道用户具体投了哪些分区，只知道回合总分。当用户输入总分==剩余分触发Checkout时，需让用户声明本回合用了几镖结镖（1镖/2镖/3镖）。但并非所有剩余分都能用任意镖数合法结镖——必须根据OUT规则动态计算每种镖数的可达性。

可达性定义：给定remaining、outMode、dartCount(k)，是否存在k镖组合（最后一镖符合OUT规则，其余镖∈单镖可达分值集合B）总和等于remaining。

function isCheckoutReachable(remaining, outMode, dartCount):
 if remaining < 1 or remaining > 180: return false
 if outMode == "STRAIGHT_OUT": return true // Straight Out任意分区都可结镖，1-3镖均可达（除remaining>180）

 // 定义OUT规则要求的最后一镖分区集合
 if outMode == "DOUBLE_OUT":
 outSet = DOUBLE_ZONE // {2,4,6,...,40,50}，共21个值
 elif outMode == "MASTER_OUT":
 outSet = DOUBLE_ZONE \| TRIPLE_ZONE // {2,3,4,...,40,42,45,48,50,51,54,57,60}，共35个值

 // 单镖所有可达分值集合 B = {1-40, 42,45,48,50,51,54,57,60}，共43个值
 B = SINGLE_ZONE \| DOUBLE_ZONE \| TRIPLE_ZONE \| {25}

 if dartCount == 1:
 return remaining in outSet
 elif dartCount == 2:
 for d1 in B:
 if (remaining - d1) in outSet: return true
 return false
 elif dartCount == 3:
 for d1 in B:
 for d2 in B:
 if (remaining - d1 - d2) in outSet: return true
 return false
 return false

## 2.7 X01 规则档位（★V1.04 新增）

X01 的开局与结束不再是两个布尔开关，而是与牛眼计分并列为三组规则档位；配置字段 inMode / outMode / bullMode 为枚举名（存库、进协议），中文文案见下表。

 ┌─────────────────────┬───────────────────────────┬────────────────────────────────────────────┐
 │ 组 │ 取值（枚举，存库/进协议） │ 判定 / 中文文案 │
 ├─────────────────────┼───────────────────────────┼────────────────────────────────────────────┤
 │ 牛眼规则 (bullMode) │ STANDARD_25_50 │ 外牛眼 25 分、内牛眼 50 分（默认） │
 │ │ BULL_50_50 │ 无论内外牛眼都按 50 分计 │
 │ 开局规则 (inMode) │ STRAIGHT_IN │ 任何落靶的镖都可以开始计分（默认） │
 │ │ DOUBLE_IN │ 第一支有效镖须命中双倍区或双倍牛眼 │
 │ │ MASTER_IN │ 第一支有效镖须命中双倍区或三倍区 │
 │ 结束规则 (outMode) │ STRAIGHT_OUT │ 任何使分数恰好归零的镖（默认） │
 │ │ DOUBLE_OUT │ 最后一镖须命中双倍区或双倍牛眼（默认 X01） │
 │ │ MASTER_OUT │ 最后一镖须命中双倍区或三倍区 │
 └─────────────────────┴───────────────────────────┴────────────────────────────────────────────┘

 ★ 命名口径（★V1.04 订正）：规则轴一律用 straight，不用 single。single 是「区域维度」（靶面单倍区），straight 是「规则维度」（是否满足开局 / 结束条件）；写成 SingleIn 会被读成「只能单倍开局」，与「直入 = 任意区域」相反。故 InMode / OutMode 取 STRAIGHT_IN / STRAIGHT_OUT，与 M6 / 服务端既有 straight \| double \| master 一致。

 ★ 三条跨档统一口径：
 ① 双倍牛眼天然算「双倍」（内牛眼 = 25 × 2）。双倍入 / 双倍出均可用双倍牛眼开镖 / 收尾，大师入 / 大师出同理；三档都不必为牛眼单开分支。
 ② MASTER_OUT 下三倍收尾合法，DOUBLE_OUT 下不合法；凡文档写过「收尾必须双倍」的绝对措辞，一律放宽为「按 outMode 判定」。
 ③ bullMode 只影响 X01 计分（BullMode.scoreOf），不改 Dart.score：牛眼原始分恒为 25、双倍牛眼 50；Cricket 的牛眼是目标位（内 bull 2 marks / 外 bull 1 mark），不受该档影响。

 ★ 兼容（老字段降级为只读派生）：doubleIn / doubleOut / overtimeRule 保留为派生投影（如 doubleOut = outMode != STRAIGHT_OUT），老协议键与 DB 老列继续可读；新写库时新旧两套同源，不会出现「doubleOut = true 但 outMode = STRAIGHT_OUT」的矛盾行。字段级细节见 §3.8。

# 3.6 最多轮数终局判定 maxRoundsJudge()（★V1.04 重写）

当比赛打满「最多轮数」(maxRounds) 仍未正常分出胜负时，由本判定产生本局胜者：★剩余分最低者获胜（与 Cricket 的「总分最高者获胜」相反，见 §4.9.8）。M4 状态机在 submitTurn 后、轮次回到第 1 席（轮数计数递增）时检查 轮数 >= maxRounds 触发；maxRounds = 0 表示不设上限、永不触发。★V1.04 变更：原 overtimeRule（min_score / diddle 双方式）已废弃，统一收敛为 min_score 口径；「争红心 (diddle)」加时与 sudden_death 状态不再存在。overtimeRule 字段降级为**只读派生投影**（等价于 maxRounds > 0），协议旧键 overtime_rule 与 max_rounds 同值并行发出（解码优先 max_rounds）。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| players | List<PlayerState> | 全员对局状态（列表顺序 = 席位顺序；含 remaining / score） |
| currentIndex | int | 触发判定时的投掷席序（0 起） |
| maxRounds | int | 每局最多轮数；0 = 无上限（不触发判定）。与 Cricket 共用同一字段 |
| 变更说明 | — | ★V1.04：原 remaining1 / remaining2 / totalScore1 / totalScore2 双人签名废弃，改为全员列表 + 剩余分最低者获胜；min_score / diddle 双方式与 sudden_death 一并废弃 |
| 触发条件 | — | 打满 maxRounds 后，在「轮次回到第 1 席」的时机触发；落库 endedByRoundLimit = true，对局页提示 "MAX ROUNDS" |

| 返回值 | 类型 | 说明 |
| --- | --- | --- |
| winnerIndex | int | 剩余分最低者席位序号（0 起）；并列最低时取席序靠前者 |
| reason | string | 判定原因："remaining_lower"（打满最多轮数且无正常获胜者） |

function maxRoundsJudge(players, currentIndex, maxRounds):
 // maxRounds = 0 表示不设上限，永不触发
 if maxRounds <= 0: return null
 if roundsCompleted < maxRounds: return null

 // 打满最多轮数 → X01 口径：剩余分最低者获胜
 winnerIndex = players.minByOrNull { it.remaining }.index // 并列取席序靠前者
 return { winnerIndex: winnerIndex, reason: "remaining_lower" }

★ 边界说明：① 判定只在「轮次回到第 1 席」时发生（轮数计数递增），保证全员投满同样轮数；② 支持 2–4 人，取剩余分最低者，并列最低时取席序靠前者，不做逐人加时；③ 触发后本局立即结束，落库 endedByRoundLimit = true，对局页显示 "MAX ROUNDS"；④ 不再存在 need_diddle / sudden_death 分支；⑤ Cricket 使用同一字段但胜负口径相反（总分最高者胜），见 §4.9.8。

# 4. Cricket 规则

★ Cricket规则（★v1.8提升为P0，详细定义）

Cricket（板球/棒球）是飞镖第二大主流游戏，目标是"关闭"指定分区并取得更高分数。与X01的"减分到0"不同，Cricket是"分区占领+得分"玩法。

4.1 目标分区
 7个目标分区：15, 16, 17, 18, 19, 20, Bull（牛眼）—— ★V1.04：目标集由配置传入（cricketTargets），默认即本 7 分区；Tactics 为 9 档、Random 为随机 5 个，见 §4.9
 非目标分区（1-14）命中无效，记0分，不影响游戏

4.2 分区关闭规则
 每个分区需累计命中3次才能"关闭"（Close）：
 单倍区(S)命中 = 1次计数
 双倍区(D)命中 = 2次计数
 三倍区(T)命中 = 3次计数
 计数达到3即关闭，超过3的部分可转化为得分（见4.3）

 Bull分区特殊规则：
 Outer Bull(25分) = 1次计数
 Bull(50分) = 2次计数
 Bull需累计3次计数关闭（与15-20一致）：Outer Bull(25分)=1次计数，Bull(50分)=2次计数。
 即：需累计3次计数方可关闭（如3次Outer，或1次Inner Bull+1次Outer，或1次Inner Bull+1次单倍牛等）。

4.3 得分规则
 分区未关闭时：命中只增加计数，不得分
 分区已关闭且对手也已关闭：命中不得分（双方都关闭的分区"死区"）
 分区已关闭但对手未关闭：命中得分（★V1.02：得分归属由 cricketVariant 决定，cut_throat 下计入对手、no_score 下不累计 —— 见 4.8）
 得分 = 命中倍数 × 分区值
 S15=15分, D15=30分, T15=45分
 S20=20分, D20=40分, T20=60分
 Outer Bull=25分, Bull=50分
 关闭当回合超出3次的部分：如果对手未关闭该分区，超出部分同样得分
 例：分区计数为2，命中T20(3次) → 计数变为5，关闭，超出2次 → 得2×20=40分

4.4 胜负判定
 获胜条件（同时满足）：
 ① 本方已关闭全部7个分区
 ② 本方总分 ≥ 对手总分（★V1.02：此条仅 standard；cut_throat 为 ≤、no_score 不比较分数 —— 见 4.8）
 双方都关闭全部分区时：分数高者获胜
 分数相同且双方都关闭：继续比赛（超轮），直到一方得分领先；若设了轮数上限，打满后按 §4.9.8 判「总分最高者胜」
 每回合 3 镖，双方轮流；缺省无回合数上限（maxRounds = 0），设上限后按 §4.9.8 判超时终局
 Cricket 不适用 targetScore / inMode / outMode / bullMode 等 X01 规则档位；整场局数由 matchMode 决定（casual = 单局即结束，multi = 多局）；轮数上限与 X01 共用 maxRounds（语义见 §4.9.8）。

4.5 Cricket状态数据结构
 CricketState = {
 player1: {
 closed: {15:false, 16:false, 17:false, 18:false, 19:false, 20:false, bull:false},
 counts: {15:0, 16:0, 17:0, 18:0, 19:0, 20:0, bull:0}, // 各分区0-3，达到3即关闭（含bull）
 score: 0
 },
 player2: { same structure }
 }

4.6 validateCricketTurn 整回合校验函数（★v1.8新增）

 function validateCricketTurn(darts, cricketState, currentPlayer):
 result = {
 updatedState: deepClone(cricketState),
 isGameOver: false,
 winner: null,
 scoreGained: 0,
 warnings: []
 }
 opponent = currentPlayer == "player1" ? "player2" : "player1"
 pState = result.updatedState[currentPlayer]
 oState = result.updatedState[opponent]

 for dart in darts:
 section = dart.section // "15"-"20" or "bull"
 if section not in ["15","16","17","18","19","20","bull"]:
 result.warnings.push("非目标分区，记0分")
 continue // 1-14分区无效

 // 计算本次命中的计数值
 if section == "bull":
 countVal = dart.score == 50 ? 2 : 1 // Bull=2次, Outer=1次
 sectionValue = dart.score // 25 or 50
 else:
 countVal = dart.multiplier == "S" ? 1 : dart.multiplier == "D" ? 2 : 3
 sectionValue = parseInt(section)

 if !pState.closed[section]:
 // 分区未关闭：增加计数
 pState.counts[section] += countVal
 if pState.counts[section] >= 3:
 // 达到关闭阈值
 pState.closed[section] = true
 // 超出3次的部分，如果对手未关闭，得分
 excess = pState.counts[section] - 3
 if excess > 0 and !oState.closed[section]:
 gained = excess * sectionValue
 pState.score += gained
 result.scoreGained += gained
 else:
 // 分区已关闭：如果对手未关闭，得分
 if !oState.closed[section]:
 gained = countVal * sectionValue
 pState.score += gained
 result.scoreGained += gained

 // 胜负判定
 allClosed = all(pState.closed.values())
 if allClosed and pState.score >= oState.score:
 result.isGameOver = true
 result.winner = currentPlayer

 return result

4.8 Cricket 玩法变体（★V1.02新增，一期 3 种）
 变体由比赛配置 cricketVariant 指定；差异体现在「得分归属」与「胜负比较」两处，另有与两轴正交的「可选得分修饰器」（轮数上限 / Overkill，见 §4.9.8、§4.9.9），
 关闭规则（每分区累计 3 次计数关闭）、回合结构（3 镖/回合、无 Bust）与 standard 完全一致；回合上限与超杀是两个可选得分修饰器，缺省为「无回合上限」（maxRounds = 0）与「无 Overkill」（overkillEnabled = false），开启后分别见 §4.9.8（轮数上限）与 §4.9.9（Overkill）。

 ① 枚举与策略映射
 CricketVariant = standard \| no_score \| cut_throat
 ScoreSink = SELF \| OPPONENTS \| NONE // 得分归属
 WinCompare = GE（≥） \| LE（≤） \| NONE // 关闭全部分区后的分数比较
 standard -> ScoreSink=SELF, WinCompare=GE （原口径，行为不变）
 no_score -> ScoreSink=NONE, WinCompare=NONE （不计分，先关满者胜）
 cut_throat -> ScoreSink=OPPONENTS, WinCompare=LE （得分给对手，低分领先）

 ② standard（标准，默认）
 得分计入本方；分区已关闭且对手未关闭时，命中得 倍数×分区值；
 胜负：关闭全部 7 个分区 且 本方总分 ≥ 对手总分。即 §4.3 / §4.4 原口径。

 ③ no_score（不计分）
 不累计任何得分：所有命中只做计数与关闭，得分恒为 0（ScoreSink=NONE）；
 胜负：先关闭全部 7 个分区者立即获胜，不比较分数；
 双方不可能在同一回合内同时达成，故不存在「同时关满」的并列判定。

 ④ cut_throat（生死局）
 得分归属对手：本方命中产生的得分计入「对手」的总分（ScoreSink=OPPONENTS）；
 胜负：关闭全部 7 个分区 且 本方总分 ≤ 对手总分 时获胜（低分领先，LE 含等号）；
 建议 3 人及以上对战；2 人对战时策略价值明显降低，M7 需给出提示。

 ⑤ 接口影响（以代码为准，禁止 M4 另立口径）
 evaluate / validate 的 scoreGained 语义随 ScoreSink 变化：
 SELF -> 计入 currentPlayer.score（原行为）
 OPPONENTS -> 计入 opponent.score，返回值须带「得分归属玩家」标识供 UI 提示
 NONE -> 恒为 0，不写入任何一方 score
 完整胜负判定 = allClosed && 按 WinCompare 比较，由 M2 返回 isGameOver / winner。

 ⑥ 与配置的关系
 cricketVariant 属 Cricket 专属配置，与 matchMode / legsToWin / aiPpr / diddleEnabled 并列；
 X01 不适用；Cricket 不使用 targetScore / inMode / outMode / bullMode 等 X01 规则档位（轮数上限除外 —— 与 X01 共用 maxRounds，见 §4.9.8）。

 ⑦ 二期标识与序列化契约（★V1.03 冻结）
 二期范围：tactics（战术局）与 random（随机局）。本条是二期的**强制前置契约**，已冻结；
 二期实现时只允许按此格式扩展，不得更改既有格式。
 a) 标识类型升级（可先行重构，行为零变更）
 分区标识由 Int 升级为值类型 —— 类别档不是数字：
 CricketTarget = Number(value) // 15..20、25(Bull)
 \| Category(kind) // DOUBLES 双倍档 \| TRIPLES 三倍档
 cricketNumbers: List<Int> 升级为 cricketTargets: List<CricketTarget>；

 b) token 语法（落盘与线协议的唯一格式）

 c) 兼容四点（红线）
 1. 未知 token 必须**跳过**而非报错：新端读旧数据行为不变，旧端读新数据不崩溃。

 4. 目标集变更**不得改列类型、不得改既有字段名**：match_players.firstClosedCsv 仍为 TEXT，

4.9 Tactics / Random 玩法（★V1.04 新增，2C 定稿 r7）
 玩法差异由 cricketTargets（目标集）承载：Tactics = 含类别档（双倍档 / 三倍档）的目标集；Random = 从默认池随机抽取的目标集。
 ★Q7 契约：Tactics / Random 不新增 CricketVariant 取值，cricketVariant 一律保持 standard；统计准入因此必须同时看目标集（见 4.9.6）。

 4.9.1 Tactics 目标集
 Tactics 目标集共三档，命名沿用「号位范围」写法：
 20→15（缺省）：20,19,18,17,16,15 + 双倍档 + 三倍档 + Bull —— 9 档，本期实现；
 20→13：上行再加 14,13 —— 11 档，后续档（参数即可放开）；
 20→12：上行再加 12 —— 12 档，后续档（参数即可放开）。
 顺序固定为：数字（20→15）→ 双倍档 → 三倍档 → Bull，UI 行序即此顺序；targetSetCsv 按此顺序编码，20→15 档即 "20,19,18,17,16,15,D,T,25"。
 三档之间只差数字目标的个数，关闭与计分机制完全相同 —— 后续放开 20→13 / 20→12 不需要任何结构改动，只是多一组目标集常量。本期只做 20→15。

 4.9.2 类别档的标记与归属裁决（本变体核心机制）
 ① 标记规则：双倍档 / 三倍档各自累计 3 个标记即关闭；每命中一个合格的双倍区 / 三倍区，对应类别档 +1 标记（不按倍数、不按面值加权）。
 ② 合格范围：仅 15–20 上的双倍 / 三倍计入（缺省即 STRICT 模式；SLOP 模式见 4.9.7）。1–14 的 D/T 不计入任何目标。Inner Bull（双倍红心）只作用于 Bull 目标本身，不计入双倍档 —— Bull 是独立目标，不是「双倍区」。
 ③ 归属裁决：当一支镖同时满足「数字目标」与「类别档」时（如 T20 →「20」或「三倍档」），必须二选一，不得同时计入两个目标。裁决在投掷时确定，且是该次投掷的属性（撤销该镖即连带撤销裁决）。
 ④ 裁决结果决定该镖的标记与得分：裁决为数字 ⇒ 按 4.2 正常加标记（T20 = 「20」+3 标记），并按 4.3 判定得分；裁决为类别 ⇒ 对应类别档 +1 标记，该镖不得分（见 4.9.3）。
 ⑤ 缺省与改判：未显式裁决时默认裁决为「数字」（与标准玩法手感一致）；提供单镖改判入口，改判窗口截止于投下一镖之前（第三镖则截止于本回合结束前）。
 ⑥ AI 裁决策略：若某类别档尚未关闭，且（本次裁决对应的数字目标已关闭，或本方全部数字目标已关闭）⇒ 裁决为类别；否则裁决为数字。

 4.9.3 类别档的得分（严格 Tactics 口径）
 ① 分数只从「数字路径」产出：一支镖被裁决为「记给数字 N」时，按 4.8 标准 Cricket 规则结算（标记 + 超额标记 × 面值）。
 ② 类别档路径只产标记、不产分：被裁决为「记给双倍档 / 三倍档」时，仅为该目标 +1 标记，该镖不产生任何分数（标记与得分互斥，同 4.9.2④）。
 ③ 死区豁免：一记 double / triple 被裁决为「记给数字 N」，且 a) N 已被全部玩家关闭；b) 本方已关闭对应的类别档；c) 该类别档尚未被全部玩家关闭 —— 三者同时满足时，该镖仍按 倍数 × N 计分（triple 19 ⇒ 57 分）。任一条件不满足 ⇒ 0 分。
 ④ ③ 的归属仍记在数字 N 名下（不记给类别档），因此不增加该类别档的标记。
 ⑤ UI 必须：在二选一控件上直接显示每个选项的即时结算结果（例：「记『19』→ +57 分」/「记『三倍档』→ +1 标记」）；命中 ③ 时在结算明细与回合历史中标注「死区豁免」来源。禁止静默。

 ⑧ 但「变体之间的差异只有两处」这句契约陈述要放宽：4.9.9 的 overkillEnabled 与本节 ③ 的死区豁免都是可选 / 附加得分修饰器，与两轴正交。

 4.9.4 Random 目标集
 ① 抽取池：15–20 + Bull（共 7 个），不引入 1–14。
 ② 抽取数量：5 个（固定，不随机）。
 ③ 不强制包含任何特定目标（含 Bull）。
 ④ 规范化顺序：抽取结果按默认目标集顺序（20→15→25）排列，不按抽中顺序。
 ⑤ 落盘：targetSetCsv = 抽中目标集的 token 串（非默认集）；不保存随机种子。
 ⑥ 抽取时机：每局（leg）开局抽取一次；多局模式下每 leg 重新抽取；同一 leg 内永久固定（见 4.9.5①）。

 4.9.5 目标集不变式
 ① 局级常量：目标集在一局（leg）开局确定，局中永不重抽、永不增删。即使某目标已被全部玩家关闭（死区），它仍留在集内并显示为已达成。
 ② 不得因关闭而重抽：关闭是永久进度，重抽会与「已关闭」语义直接冲突。
 ③ 非空保证：目标集必须非空。任何解析 / 抽取路径遇到空集，一律回落 DEFAULT_TARGETS。
 ④ 可达性保证：目标集中每个 Number 目标都必须能被 Dart 表达，且必须能被 AI 选点产出（不得出现只有人类可关闭的目标）。
 ⑤ 规模下限：目标集元素个数 ≥ 4。

 4.9.6 tactics / random 的统计与成就准入
 ① 事实统计全计入：对局数、镖数、胜场等事实类统计，tactics / random 与一期三种变体一致，全部计入。
 ② 所有 Cricket 衍生指标仅 standard：C1 / C2 / C3 / C4 / C5 / C6 / C7 / C8 / C9 / C10 全部仅 standard 计入。
 ③ Cricket 组成就 6 项仅 standard 计入（与一期变体一致）；变体局仍计入里程碑组「对局数合计」。
 ④ 准入判据在既有判据上「增加目标集那一半」，而非替换：一笔 Cricket 对局计入衍生指标，当且仅当它同时满足三段 —— gameType = CRICKET 且 cricketVariant = standard 且 目标集为 DEFAULT_TARGETS（即 targetSetCsv 为空串）。若未来出现「standard + 自定义目标集」的组合，同样不计入。
 · 不能只按变体名：variant 那半仍必须保留，用于挡 no_score / cut_throat —— 它们与标准局共用默认目标集，targetSetCsv 同样为空串。
 · 也不能只按目标集：目标集那半用于挡 Tactics / Random —— 它们的 cricketVariant 仍是 standard。两半缺一都会放错样本。
 ⑤ 代价：tactics / random 在统计页只贡献事实数据；若后续要给 tactics 单独出指标，应当单列一套，而不是并入 standard 口径。

 4.9.7 严格性档位（STRICT / SLOP）
 ① Tactics 有 STRICT / SLOP 两档，只影响 4.9.2② 的「合格」判定：STRICT（缺省）只有 15–20 上的双倍 / 三倍计入双倍档 / 三倍档；SLOP 则 1–20 全盘任何双倍 / 三倍都计入。
 ② 两档只放宽「合格」判定，不改标记数（每命中仍 +1）、不改计分、不改二选一的机制。本期只实现 STRICT，SLOP 记为后续档。
 ③ 口径确认：Bull 永不判为「双倍区」（categoryFor 永久返回 null），SLOP 下也不计入双倍档。

 4.9.8 轮数上限（与 X01「最多轮数」为同一配置字段）
 ① 通用 Cricket 配置项 maxRounds（每人回合数上限），取值 0 = 无上限（缺省）、15（对齐软镖机）、20、50、80。
 ② 缺省 0 使一期契约完全不变：standard / cut_throat / no_score 三种变体在缺省下行为与一期逐位一致。
 ③ tactics 缺省 50 轮（对齐参考实现），玩家可改。
 ④ 到达上限时的终局判定：若在最后一个回合结束时无人满足获胜条件，则总分最高者胜（不再读 WinCompare）。
 ⑤ 超时终局的局同样计入 match_records，并以 endedByRoundLimit 布尔列标注（缺省 false）；该局不计入 closedAllSectionLegs（关满局数）。
 ⑥ 与 X01 的关系：轮数上限与 X01「最多轮数」是同一个配置字段 maxRounds（语义、计数单位「每人各投一轮记 1」、候选值 [0,15,20,50,80] 逐项相同）；差别只在超时终局谁领先 —— X01 剩余分最低者胜（§3.6）、Cricket 总分最高者胜。同一局只会有一个玩法在读它。
 ⑦ 已知口径差异（待产品裁决）：本文档原写「通用配置项」，实现上仅在 Tactics 曝光；若全玩法开放，cut_throat 会出现「超时后最高分者胜 = 颁给局面最差者」、no_score 全场 0 分会退化为「轮到者胜」。故当前曝光范围收窄为 tactics。

 4.9.9 Overkill（超杀）
 ① 新增通用 Cricket 配置项 overkillEnabled（布尔），缺省 false（关闭）。
 ② 触发条件：结算一镖时，若投掷者当前 score 领先所有对手中的最高分 ≥ 200，则该镖的得分作废（scoreGained = 0、scoreOwnerIds = ∅）。
 ③ 标记不受影响：该镖的 marksGained 照常计入，关门进度与胜利条件完全不受 Overkill 影响。
 ④ 作用域：仅对 ScoreSink.SELF 的变体开放（standard / tactics，含随机目标）。cut_throat 的「领先」语义相反、no_score 无分可限 —— 两者不提供该开关。
 ⑤ 必须是「动态判定」而不是「一次性锁存」：每镖按当时的实时分差判定；对手得分把分差拉回 200 以内后，领先方恢复计分。
 ⑥ 必须给玩家提示：被 Overkill 抑制的镖，UI 须明确显示「超杀·得分不计」。静默不计分是本项目明确禁止的行为。
 ⑦ 阈值固定 200，不可配，只提供开关。

 4.9.10 模式命名与文案
 ① 模式名定为 Tactics（中文界面建议并列释义，如「Tactics 战术飞镖」）。
 ② hint 必须写全含 D/T 档，例如：「标准 Cricket 再加两个目标 —— 双倍档、三倍档，各需 3 个标记；打出双倍 / 三倍区时要二选一记哪个目标」。
 ③ 禁止在文案里写「Tactics 就是标准 Cricket」「英式 Cricket」这类说法 —— 在国内镖馆语境下会被理解成「和标准一样」，是反向误导。
 ④ Overkill 开关放到所有 Cricket 模式（它是标准 Cricket 的规则），但只对计分变体可见。
 ⑤ 术语只保留一套叫法：目标集统一称「20→15 / 20→13 / 20→12」；类别档统一称「双倍档 / 三倍档」。
 影响面：纯 M7 文案，无代码改动；M7 P7.1 验收须加两条（hint 必须提到「双倍档 / 三倍档」与「二选一」；列表页就要能看出与标准不同）。
