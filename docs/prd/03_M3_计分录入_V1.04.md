# 1. 模块概述

M3 计分录入模块负责飞镖比赛中的分数录入交互。核心是模式切换器——在分数输入框左侧提供3种输入模式切换。v1.2核心变更：撤销逻辑从"逐镖编辑模式"简化为"逐镖回退"，每次点撤销回退最后一镖，回退后直接重新输入，彻底取消编辑状态机。

## 1.1 三种输入模式

| 模式 | 优先级 | 录入粒度 | 核心交互 | 适用场景 |
| --- | --- | --- | --- | --- |
| 逐镖分区 | P0（默认） | 逐镖 | 先选倍数(S默认/D/T)再用0-9键盘输入1-20，Bull/Outer独立按钮一键填入；自动填入镖位；逐镖回退撤销 | 需要记录每镖具体分区（X01/Cricket通用） |
| 快速总分 | P0 | 整回合 | 直接输入回合总分0-180或点快捷分数，点"下一选手"提交；Checkout时弹窗确认结镖镖数 | 知道总分，最快录入（仅X01，Cricket不支持） |
| 靶盘点击 | P1 | 逐镖 | 点击大靶盘图落点自动识别分区 | 精确记录落点（X01/Cricket通用） |

## 1.2 模块职责（v1.2更新）

- • 模式切换器组件（3种模式切换）
- • 逐镖分区模式：倍数选择器(S默认/D/T)+Bull/Outer独立按钮+0-9键盘(仅1-20)+3镖位+自动填入（0.8s延时）+逐镖回退撤销
- • 快速总分模式：总分输入+快捷分数+Checkout确认弹窗+实时预校验
- • ★v1.3统计限制：快速总分模式仅记录回合总分，不记录每镖具体分区；基于每镖的统计指标（T20命中率、三倍区占比、平均每镖得分分布、结镖路线分析）在此模式下不可用，M9必须过滤input_mode=quick_total的回合（Checkout回合的checkoutDarts可用于结镖镖数分布统计）
- • 靶盘点击模式（P1）
- • "下一选手"按钮（M3内部管理，3镖完成或输入总分后激活）
- • ★逐镖撤销：点撤销回退最后一镖，回退后直接重新输入（v1.2新逻辑，取代编辑模式）
- • Bust按钮（两种模式统一：只激活"下一选手"，不自动提交）
- • 语音输入（全局浮动按钮）
- • 快捷按钮设置（逐镖快捷/总分快捷两组）
- • 输入预校验（Bust预警/Checkout提示）

 remaining=171：1镖✗ 2镖✗ 3镖✗(>170) → 仅[爆镖][取消]（无法合法结镖，只能爆镖）

 示例（Master Out）：
 remaining=60：1镖✓(T20) 2镖✓ 3镖✓ → 5选项全显示
 remaining=140：1镖✗(>60) 2镖✗(>120) 3镖✓ → 3选项[3镖][爆镖][取消]
 remaining=180：1镖✗ 2镖✗ 3镖✓(T20×3=180) → 3选项

 快速判断上限（Double Out）：1镖max=50，2镖max=110，3镖max=170
 快速判断上限（Master Out）：1镖max=60，2镖max=120，3镖max=180
 超过上限的镖数选项直接不可用。

 各选项行为：
 选1镖/2镖/3镖（仅可达选项可点）：
 → checkoutDartCount = 选中值（1/2/3）
 → 调用M2.validateTurn(..., inputMode="quick_total", isCheckoutConfirmed=true, checkoutDartCount=k)
 → M2校验isCheckoutReachable通过 → isCheckout=true，提交回合，结束本局
 → darts拆分：第1条=inputTotal(label="TOTAL")，第2/3条=MISS
 → input_source = "quick_total"
 → checkoutDarts字段记录实际结镖镖数（用于统计）

 选爆镖：
 → isBust = true，turnScore = 0，darts全部MISS
 → 触发 onNextPlayer({isBust:true, turnScore:0})
 → M4判定Bust，剩余分不变，切换选手

 选取消：
 → 关闭弹窗，回到输入状态，输入框保留原值，不提交

 ★ v1.5重要变更：不再有"静默跳过OUT校验"。用户选择的镖数若不可达，弹窗根本不显示该选项；
 若所有镖数均不可达（如remaining=171 Double Out），用户只能选"爆镖"或"取消"。
 这保证了快速总分模式下OUT规则的正确性，与逐镖模式的OUT校验逻辑对齐。

★ OUT规则非法分数列表（★v1.5新增，与IN规则对称，用于Checkout场景快速判断）：

# 8. 开发实况回写 输入方式与逐镖点位

本节为 V1.03 的权威增补；当本节与旧版 §5.3–§5.4 的“靶盘点击 P1 锁态”或“保存到 user_settings”描述冲突时，以本节为准。

## 8.1 输入方式与录入模式是两个维度

| 维度 | 候选 | 当前状态 | 作用 |
| --- | --- | --- | --- |
| 输入方式 InputMode | KEYPAD / BOARD / AI_VISION | 键盘与靶盘可用；AI 视觉灰态预留 | 决定这一镖如何录入 |
| 录入模式 | 逐镖分区 / 快速总分 | 沿用既有规划 | 决定这一局按何种粒度录入 |

- 输入方式切换器位于输入区顶部右端，尺寸 96×44dp；默认 KEYPAD。
- 输入方式只在当前会话内通过 rememberSaveable 保留；冷启动回到键盘。跨会话偏好键 input.mode 为后续待办。
- InputMode 仅作用于 X01；Cricket 本轮不接入。两种维度不得合并为同一个下拉菜单。
## 8.2 靶盘点击与几何判定

- 点击坐标先由 BoardLayout 从画布坐标换算为靶面毫米坐标，再交给 BoardGeometry.dartAt() 判分；不新增第二套判分规则。
- 靶面坐标原点为靶心，x 向右、y 向上；画布 y 轴翻转只在 BoardLayout 执行一次。手点与 M12 视觉共用同一坐标系和环宽常量。
- 功能键为 MISS、撤销、确认、输入方式。靶盘模式下前三键在盘下等宽排列；键盘原有布局不变。
- 手点误差约 ±3–5mm，而双倍环和三倍环宽为 8mm。点位热力图适合观察趋势，不足以证明贴边单镖是否实际命中目标环。
## 8.3 数据采集契约

- source = DartSource.BOARD_TAP；键盘、AI 托管镖不产生手点点位。MISS 可保存坐标或通过 MISS 键录入无坐标结果。
- 点位与整场记录同批写入；中途退出不落库，提交后立即清空 pendingHits。
- 逐镖表、迁移链和索引以 T3 数据库 Schema §8 为准。
# 9. 主题语义与 Android 尺寸适配

本节为当前实现与验收口径，覆盖旧页面表格中的固定颜色名称与 pt 尺寸。业务状态含义不变，视觉实现统一引用 M1 与 T1 的语义 Token。

| 既有描述 | 当前语义 | 实现要求 |
| --- | --- | --- |
| 无效输入、Bust、错误红色 | Error / OnError / ErrorContainer | 必须同时显示错误文案或图标，不得只靠颜色 |
| 将 Bust、预警黄色 | Warning / OnWarning / WarningContainer | 保留警告图标和提示文案 |
| Checkout 绿色 | Success / OnSuccess / SuccessContainer | 保留 Checkout 文案或成功图标 |
| 下一选手、保存等主要按钮 | Primary / OnPrimary | 按动作层级使用主操作样式，不把绿色作为验收条件 |
| 灰态、禁用、待覆盖 | OnSurfaceVariant / Disabled | 同时提供禁用语义、透明度或形状反馈 |
| 勾选和当前模式 | Primary 或 Secondary | 必须同时保留勾选图标及可访问状态 |

- 旧 44×44pt、48pt、40pt 等数值只保留为历史候选，不作为 Android 验收值；控件、热区和间距统一消费 Size、Spacing Token，布局使用 dp，字号使用 sp。
- 靶盘颜色与热力反馈引用 T1 §15；手点和视觉计分继续共用 BoardGeometry，不因主题变化改变判分。
- 主题替换后，输入模式、选中、错误、警告、成功和禁用状态的业务含义不得变化。
