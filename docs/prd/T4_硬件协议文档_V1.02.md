# 1. 概述

## 1.1 两种硬件形态

| 维度 | 高端硬件（Pro） | 低端硬件（Lite） |
| --- | --- | --- |
| 组成 | 三摄像头+主控盒（OpenCV自动计分） | 标靶斜上方摄像头+WiFi传输模块 |
| 核心能力 | 自动识别每镖落点，逐镖计分 | 仅提供靶盘实时画面，计分靠语音/手动 |
| 与手机通信 | WebSocket（JSON-RPC 2.0） | RTSP（H.264视频流） |
| 互联网连接 | 不连互联网，手机作网关 | 通过WiFi连接手机/路由器 |
| 协议端口 | 8080（WebSocket） | 8554（RTSP） |
| 发现方式 | 蓝牙广播 + mDNS | mDNS + 设备AP扫描 |
| 认证 | 绑定Token（首次配网生成） | 设备PIN码（8位，底部标签） |

## 1.2 通用规范

| 项目 | 规范 |
| --- | --- |
| 字节序 | 大端序（Big-Endian / Network Byte Order） |
| 字符编码 | UTF-8 |
| 时间戳 | Unix毫秒时间戳（uint64），UTC |
| JSON格式 | 紧凑JSON（无空格），字段名小写下划线 |
| 版本协商 | 连接后第一个消息交换协议版本，不兼容则断开 |
| 心跳 | WebSocket保活：客户端每10秒ping，3次无响应（30秒）断开重连；设备状态心跳：设备每30秒上报heartbeat（3次无心跳90秒判离线，仅高端） |
| 重连 | 指数退避（1s/2s/4s/8s/16s/30s），最多10次 |
| 错误处理 | 所有请求都有响应，错误响应含code和message |
| 幂等 | 写操作带request_id，重复请求返回相同结果 |

# 2. 配网协议（通用）

两种硬件的配网流程相同：蓝牙发现 → 蓝牙连接 → WiFi配置 → 设备联网 → 绑定验证。配网阶段使用蓝牙GATT通信，配置完成后切换到WiFi通信。

## 2.1 蓝牙GATT服务

| 项目 | 值 |
| --- | --- |
| Service UUID | 0000ffe0-0000-1000-8000-00805f9b34fb（DartVio配网服务） |
| Characteristic UUID（写） | 0000ffe1-0000-1000-8000-00805f9b34fb（手机→设备） |
| Characteristic UUID（通知） | 0000ffe2-0000-1000-8000-00805f9b34fb（设备→手机） |
| MTU | 244字节（协商后） |
| 广播名称 | DartVio-Pro-XXXX / DartVio-Lite-XXXX（XXXX为MAC后4位） |
| 广播间隔 | 100ms（配网模式） |
| 配网模式超时 | 5分钟（未被连接则退出配网模式） |

## 2.2 配网指令集（蓝牙GATT）

| 指令 | 方向 | 数据 | 说明 |
| --- | --- | --- | --- |
| BLE_HELLO | 手机→设备 | {"type":"hello","protocol_version":1} | 连接后握手，设备返回设备信息 |
| BLE_HELLO_ACK | 设备→手机 | {"type":"hello_ack","device_id":"...","device_type":"pro","model":"...","firmware_version":"...","mac":"..."} | 设备信息响应 |
| BLE_WIFI_SCAN | 手机→设备 | {"type":"wifi_scan"} | 请求设备扫描附近WiFi |
| BLE_WIFI_LIST | 设备→手机 | {"type":"wifi_list","networks":[{"ssid":"...","rssi":-55,"security":"wpa2"},...]} | WiFi列表（扫描可能需要3-5秒） |
| BLE_WIFI_CONFIG | 手机→设备 | {"type":"wifi_config","ssid":"Home-5G","password":"...","security":"wpa2"} | 配置设备WiFi（密码加密传输） |
| BLE_WIFI_STATUS | 设备→手机 | {"type":"wifi_status","status":"connecting/connected/failed","ip":"192.168.1.100","error":"..."} | WiFi连接状态实时推送 |
| BLE_BIND | 手机→设备 | {"type":"bind","user_id":"DV_XXXX","bind_token":"..."}（高端）/ {"type":"bind","user_id":"...","pin_code":"12345678"}（低端） | 发起绑定 |
| BLE_BIND_ACK | 设备→手机 | {"type":"bind_ack","success":true,"device_id":"...","bind_token":"..."} | 绑定结果 |
| BLE_REBOOT | 手机→设备 | {"type":"reboot"} | 绑定成功后重启设备（切换到正常模式） |

## 2.4 配网错误码

| 错误码 | 说明 | 处理建议 |
| --- | --- | --- |
| BLE_ERR_1001 | 蓝牙未开启 | 提示用户开启蓝牙 |
| BLE_ERR_1002 | 蓝牙连接失败 | 靠近设备，重试 |
| BLE_ERR_1003 | GATT服务不存在 | 设备固件版本不兼容，检查更新 |
| BLE_ERR_2001 | WiFi扫描失败 | 设备WiFi模块异常，重启设备 |
| BLE_ERR_2002 | WiFi密码错误 | 重新输入密码 |
| BLE_ERR_2003 | WiFi不支持5GHz | 设备仅支持2.4GHz，切换到2.4G网络 |
| BLE_ERR_2004 | WiFi连接超时 | 路由器信号弱，靠近路由器 |
| BLE_ERR_2005 | WiFi获取IP失败 | 路由器DHCP问题，检查路由器设置 |
| BLE_ERR_3001 | PIN码错误（低端） | 检查设备底部标签，重新输入8位PIN |
| BLE_ERR_3002 | 设备已被绑定 | 设备已绑定其他用户，需先解绑 |
| BLE_ERR_3003 | 绑定Token无效 | 重新配网生成新Token |
| BLE_ERR_4001 | 协议版本不兼容 | 升级App或设备固件 |
| BLE_ERR_4002 | 配网超时 | 配网超过5分钟，重新进入配网模式 |

# 3. 高端硬件 WebSocket 协议

## 3.1 连接信息

| 项目 | 值 |
| --- | --- |
| 协议 | WebSocket (RFC 6455) |
| URL | ws://<device-ip>:8080/ws |
| 认证 | 连接时Header携带 X-Bind-Token: <bind_token> |
| 消息格式 | JSON-RPC 2.0（请求/响应）+ JSON事件（设备推送） |
| 心跳 | 连接保活：客户端每10秒 {"jsonrpc":"2.0","method":"ping","id":N}，设备回复pong；设备状态心跳事件heartbeat每30秒推送（见§6.1） |
| 最大消息大小 | 64KB（单条JSON消息） |
| 二进制消息 | 不支持（高端硬件全JSON通信） |

## 3.5 核心数据格式

### 3.5.1 dart_detected（镖识别结果）

{
 "type": "dart_detected",
 "data": {
 "timestamp": 1693900800123,
 "dart_index": 1,
 "label": "T20",
 "number": 20,
 "multiplier": 3,
 "score": 60,
 "confidence": 0.95,
 "camera_id": "cam_top",
 "position": {
 "x": 0.02,
 "y": -0.15,
 "z": 0.0
 },
 "raw_image_ref": "frame_000123.jpg"
 }
}

// 字段说明：
// label: 分区标签（S1-S20=单倍, D1-D20=双倍, T1-T20=三倍, BULL=外牛25, BULLSEYE=内牛(红心)50, MISS=脱靶）
// number: 分区数字（1-20，Bull=25，MISS=0）
// multiplier: 倍数（1=单倍, 2=双倍, 3=三倍，MISS=0）；外牛BULL: number=25,multiplier=1→25分；内牛BULLSEYE: number=25,multiplier=2→50分
// score: number × multiplier
// confidence: 0.0-1.0，<0.9触发low_confidence_warning
// position: 落点坐标（mm，红心为原点，x右正y上正）
// raw_image_ref: 原始帧文件名（设备本地存储，调试用）

# 4. 低端硬件 RTSP 协议

## 4.1 连接信息

| 项目 | 值 |
| --- | --- |
| 协议 | RTSP (RFC 2326) over TCP |
| URL | rtsp://<device-ip>:8554/stream |
| 认证 | RTSP DIGEST认证，用户名admin，密码为设备PIN码 |
| 视频编码 | H.264 (AVC)，Main Profile |
| 分辨率 | 1080p (1920×1080)，可降级720p/480p |
| 帧率 | 30fps（默认），可配置20fps |
| 码率 | 2Mbps（默认），范围1-4Mbps |
| 关键帧间隔 | 2秒（60帧@30fps） |
| 音频 | 不传输（仅视频） |
| 传输方式 | RTP over TCP (interleaved)，或RTP over UDP |
| 延迟目标 | <200ms（局域网） |

## 4.2 RTSP 交互流程

客户端（手机App） 低端硬件设备
 │ │
 │── OPTIONS rtsp://.../stream ─────>│
 │<── 200 OK (Public: OPTIONS, │
 │ DESCRIBE, SETUP, PLAY) ───│
 │ │
 │── DESCRIBE rtsp://.../stream ────>│
 │<── 200 OK (SDP: H.264, 1080p, │
 │ 90000Hz, sprop-params) ───│
 │ │
 │── SETUP rtsp://.../stream/trackID=0>│
 │ (Transport: RTP/AVP/TCP; │
 │ interleaved=0-1) │
 │<── 200 OK (Session: abc123) ──────│
 │ │
 │── PLAY rtsp://.../stream ─────────>│
 │ (Session: abc123) │
 │<── 200 OK (RTP-Info: seq=..., │
 │ rtptime=...) ──────────────│
 │ │
 │ (开始接收RTP视频流，H.264解码) │
 │ (实时渲染到对局页视频区域) │
 │ │
 │ 停止观看 │
 │── TEARDOWN rtsp://.../stream ─────>│
 │ (Session: abc123) │
 │<── 200 OK ─────────────────────────│

t=0 0

# 5. OTA 固件升级协议

两种硬件均支持OTA升级，协议相同。升级流程：检查新版本 → 下载固件 → MD5校验 → 写入Flash → 重启切换分区。

## 5.1 OTA流程

客户端App 硬件设备 OTA服务器
 │ │ │
 │── get_firmware_version ─────────>│ │
 │<── {version: "v1.2.3"} ──────────│ │
 │ │ │
 │ 检查服务端是否有新版本 │ │
 │── GET /api/ota/check?model=... ───────────────────────────────>│
 │<── {latest: "v1.3.0", url: "...", md5: "...", size: 2097152}─│
 │ │ │
 │ 提示用户有新版本，确认升级 │ │
 │── start_ota(version, url, md5) ─>│ │
 │ │ 从URL下载固件 │
 │<── ota_progress(percent=10%) ────│ │
 │<── ota_progress(percent=50%) ────│ │
 │<── ota_progress(percent=90%) ────│ │
 │ │ MD5校验 │
 │ │ 写入备用Flash分区 │
 │<── ota_progress(percent=100%) ───│ │
 │<── ota_completed(success=true) ──│ │
 │ │ │
 │ 提示用户升级完成，重启设备 │ │
 │── reboot ────────────────────────>│ │
 │ (设备重启，切换到新固件分区) │ │
 │ │ │
 │ 重新连接设备，验证固件版本 │ │
 │── get_firmware_version ─────────>│ │
 │<── {version: "v1.3.0"} ──────────│ │
 │ 升级成功 │ │

## 5.2 OTA状态定义

| 状态 | 说明 | 可操作 |
| --- | --- | --- |
| idle | 空闲，无升级进行中 | start_ota |
| downloading | 正在下载固件 | get_ota_status（查看进度） |
| verifying | MD5校验中 | get_ota_status |
| installing | 写入Flash中 | get_ota_status |
| completed | 升级完成，等待重启 | reboot |
| failed | 升级失败（含失败原因） | start_ota（重试） |

## 5.3 OTA错误码

| 错误码 | 说明 |
| --- | --- |
| OTA_ERR_4001 | 固件下载失败（网络错误/URL无效） |
| OTA_ERR_4002 | MD5校验失败（固件损坏） |
| OTA_ERR_4003 | 固件版本不兼容（型号不匹配） |
| OTA_ERR_4004 | 固件大小超出Flash容量 |
| OTA_ERR_4005 | Flash写入失败 |
| OTA_ERR_4006 | 升级中断（设备重启/断电） |
| OTA_ERR_4007 | 当前正在升级中（重复调用） |
| OTA_ERR_4008 | 电量不足（电池供电设备，需>30%） |

# 8. 实现状态与接口边界

实现状态：目标态（未实现）。当前 Android 工程没有 BLE 配网、高端硬件 WebSocket、低端 RTSP、mDNS 硬件发现或 OTA 实现；本文 §2–§6 是设计规格。CAMERA 权限属于 M12 手机视觉，不能作为 M8 硬件链路已实现的证据。

## 8.1 8080 同号边界

- 高端硬件在 <device-ip>:8080 提供 WebSocket /ws；低端硬件在同端口提供 HTTP 控制，视频使用 rtsp://<device-ip>:8554/stream。
- M5 手机房间主机同样监听 8080，但位于手机主机，WebSocket 为 /ws/v1，REST 为 /api/v1。同号不同主机，不构成冲突，硬件端口保持 8080。
- 硬件与手机同在一条 WiFi 时可以并存；设备 AP 直连导致手机脱离房间局域网时，不可同时充当 M5 主机。该限制来自拓扑，不是端口。
## 8.2 来源和识别责任

| 数据链路 | 来源 token | 质量 | 责任模块 |
| --- | --- | --- | --- |
| 高端硬件直接输出分值 | HARDWARE_VISION | CERTIFIED | M8 |
| 低端硬件输出 RTSP 画面 | PHONE_VISION | SEMI_AUTO | M12 负责画面到候选分值；用户确认或修正 |
