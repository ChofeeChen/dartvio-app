# 1. 产品概述

## 1.1 产品定位

DartVio 是一款面向飞镖爱好者的 Android App，配合两种硬件形态 + 手机视觉计分（M12）使用：

- • 高端硬件：三摄像头+主控盒+OpenCV自动计分，专业级体验
- • 低端硬件：标靶摄像头+WiFi视频流，入门级体验
- • 手机视觉计分（M12）：手机自带摄像头自动识别落点，零外置电子硬件，半自动辅助计分（新增）
核心能力：本地2人比赛、在线对战、练习模式、AI对手对战（入门/进阶/高手/专业，同级自适应）、统计分析、好友社交。对标 Dartsmind 和"好镖"app，在硬件自动计分和在线视频对战方面形成差异化。

★自动计分结果共用契约（V1.00 新增）：M8 外置硬件自动计分与 M12 手机视觉计分均只产出 Dart(number, multiplier) + confidence(0..1) + input_source（分别为 hardware_vision / phone_vision）；判定与计分统一由 M2 规则引擎处理（X01Rules.applyTurn / CricketRules.applyTurn），两者对 M2 完全等价、规则引擎零改动。M9 依据 input_source 区分数据质量：仅 hardware_vision 可标注「硬件认证」，phone_vision 为中等质量。

# 7. 文档管理规范

## 7.1 命名规范

总览文档： 00_产品总览与架构_V1.0X.docx
专题文档： TN_专题名_V1.0X.docx（N 为专题序号，现为 T1–T6）
模块文档： NN_M{NN}_模块名_V1.0X.docx（NN = 01–12，且必须等于模块号）
示例： 00_产品总览与架构_V1.03.docx　01_M1_基础设施_V1.01.docx　12_M12_手机视觉计分_V1.03.docx　T5_测试验收与环境设备_V1.02.docx
规则：① 全部正式文档必须直接位于 PRD 根目录，不得放入任何子目录；② 名称段使用中文并以「_」分隔，除固定分隔符外不得出现多余下划线；③ 版本号为大写 V + 两位小数（V1.0X），禁用 vX.Y 旧格式；④ 同一文档在磁盘上只允许存在一个当前版本，被取代版本必须移出根目录；⑤ 三处对齐：文件名版本 = 封面版本声明 = 变更记录首数据行，三者必须一致。

## 7.2 版本号管理

| 版本类型 | 规则 | 触发条件 |
| --- | --- | --- |
| 全局版本（总览文档） | vX.Y | 新增/删除模块、架构变更、跨模块接口变更 |
| 模块版本（各模块文档） | vX.Y | 模块内功能变更、UI调整、接口修改 |
| 主版本号X | 不兼容变更 | 接口签名变更、数据模型破坏性变更、模块拆分/合并 |
| 次版本号Y | 兼容变更 | 新增功能、UI优化、Bug修复、文档完善 |

## 7.3 变更记录要求

每份文档开头必须包含变更记录表，字段：版本/日期/变更类型/变更内容/影响范围/变更原因。

跨模块变更时，需在总览文档的全局变更记录中登记，并在受影响的各模块文档变更记录中引用全局变更编号。

- 6. API接口表可直接生成协议定义和网络层代码
