# 1. 模块概述

M8 硬件接入模块负责DartVio两种硬件形态的设备管理和数据接入：高端硬件（三摄像头+主控盒+OpenCV自动计分）和低端硬件（标靶摄像头+WiFi视频流）。M8提供设备发现、配网、绑定、连接管理、数据接收、视频流渲染等能力。

## 1.1 两种硬件形态

| 维度 | 高端硬件 | 低端硬件 |
| --- | --- | --- |
| 组成 | 三摄像头+主控盒+OpenCV | 标靶斜上方摄像头+WiFi传输模块 |
| 核心能力 | 自动识别每镖落点，逐镖计分 | 仅提供靶盘实时画面，计分靠语音/手动 |
| 互联网连接 | 不连互联网，手机作网关 | 通过WiFi连接手机/路由器 |
| 适用场景 | 专业/商用/高付费意愿 | 个人/入门/低付费意愿 |
| 在线对战 | 自动计分+实时同步 | 视频流推送给对手看靶盘画面 |
| 开发优先级 | P1 | P1 |

## 1.2 模块职责

- • 设备列表管理（已绑定设备的展示和管理）
- • 设备发现（蓝牙扫描附近未配网设备）
- • 配网引导（蓝牙发现→WiFi配置→设备联网→绑定）
- • 设备连接管理（连接/断开/重连/状态监控）
- • 高端硬件：自动计分数据接收和解析（每镖落点/置信度）
- • 低端硬件：视频流接收和渲染（H.264解码/实时画面显示）
- • 在线对战视频流推送（低端硬件，轮到谁显示谁的靶盘）
- • 设备固件版本检测和OTA升级（P2）
- • 设备详情（设备信息/WiFi信号/摄像头状态/解绑/重命名）

| 属于M8 | 不属于M8 |
| --- | --- |

# 2. 硬件通信协议

## 2.1 高端硬件协议

| 项目 | 说明 |
| --- | --- |
| 连接方式 | WiFi局域网（设备创建AP或连接同一路由器），手机作互联网网关 |
| 传输协议 | WebSocket（JSON-RPC 2.0） |
| 默认端口 | 8080 |
| 发现方式 | 蓝牙广播设备名称（DartVio-Pro-XXXX）+ mDNS |
| 认证方式 | 设备绑定Token（首次配网时生成，存储在设备和手机两端） |

## 2.2 高端硬件数据格式

// 设备推送：每镖识别结果
{
 "type": "dart_detected",
 "timestamp": 1693900800123,
 "dartIndex": 1,
 "label": "T20",
 "number": 20,
 "multiplier": 3,
 "score": 60,
 "confidence": 0.95,
 "cameraId": "cam_top",
 "position": { "x": 0.02, "y": -0.15, "z": 0.0 },
 "raw_image_ref": "frame_000123.jpg"
}

// 设备推送：回合完成
{
 "type": "turn_complete",
 "timestamp": 1693900805456,
 "turnNumber": 3,
 "darts": [
 { "dartIndex": 1, "label": "T20", "score": 60, "confidence": 0.95 },
 { "dartIndex": 2, "label": "S20", "score": 20, "confidence": 0.98 },
 { "dartIndex": 3, "label": "S5", "score": 5, "confidence": 0.92 }
 ],
 "totalScore": 85,
 "avgConfidence": 0.95
}

// 手机发送：确认回合
{
 "jsonrpc": "2.0",
 "method": "confirm_turn",
 "params": { "turnNumber": 3, "confirmed": true },
 "id": 1
}

// 手机发送：修正镖分数
{
 "jsonrpc": "2.0",
 "method": "correct_dart",
 "params": { "turnNumber": 3, "dartIndex": 2, "correctLabel": "S19", "correctScore": 19 },
 "id": 2
}

## 2.3 低端硬件协议

| 项目 | 说明 |
| --- | --- |
| 连接方式 | WiFi（设备连接同一路由器，或设备创建AP） |
| 视频协议 | RTSP（H.264编码，1080p@30fps） |
| RTSP地址 | rtsp://<device-ip>:8554/stream |
| 发现方式 | mDNS（_dartvio._tcp.local）+ 设备AP扫描 |
| 认证方式 | 设备PIN码（8位，设备底部标签） |
| 音频 | 不传输音频（仅视频） |
| 延迟目标 | <500ms（局域网内） |

# 4. 数据模型

## 4.1 Device（设备）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| deviceId | string | 设备唯一ID（MAC地址哈希） |
| deviceName | string | 设备名称（用户可自定义，默认"DartVio设备"） |
| deviceType | enum | pro（高端）/ lite（低端） |
| model | string | 设备型号（如DV-PRO-01/DV-LITE-01） |
| firmwareVersion | string | 固件版本号 |
| bindToken | string | 绑定Token（高端硬件认证用） |
| pinCode | string | 设备PIN码（低端硬件，8位） |
| wifiSsid | string | 连接的WiFi SSID |
| ipAddress | string | 设备局域网IP地址 |
| rtspUrl | string | RTSP视频流地址（低端） |
| status | enum | online（在线）/ offline（离线）/ connecting（连接中）/ updating（升级中） |
| wifiSignal | int | WiFi信号强度（-100到0 dBm） |
| cameraStatus | json | 各摄像头状态（高端：top/left/right，低端：single） |
| lastConnectedAt | datetime | 最后连接时间 |
| createdAt | datetime | 绑定时间 |

#### ③ 交互流程图

进入设备列表页
 → 调用 getDeviceList() 获取已绑定设备
 → 对每个在线设备尝试获取实时状态（WiFi信号/摄像头状态）
 → 注册设备状态变化监听（onDeviceStatusChanged）
 → 渲染设备列表

用户点击"添加设备" (#btn-add-device)
 → Navigation.push(AddDeviceViewController)

用户点击"连接" (#btn-connect)
 → 高端设备：调用 connectDevice(deviceId) → 建立WebSocket连接
 → 低端设备：调用 connectDevice(deviceId) → 建立RTSP连接
 → 连接中按钮显示加载动画
 → 成功 → 按钮变为"已连接"绿色，设备状态更新为在线
 → 失败 → Toast"连接失败，请检查设备是否通电且在同一WiFi"，按钮恢复

用户点击"重连" (#btn-reconnect)
 → 同连接流程，尝试重新建立连接

用户点击"详情" (#btn-detail)
 → Navigation.push(DeviceDetailViewController(deviceId))

用户左滑设备卡片 → 点击"解绑" (#btn-unbind)
 → 确认弹窗"确定解绑设备？解绑后需重新配网才能使用"
 → 确认 → 调用 unbindDevice(deviceId) → 从列表移除
 → 取消 → 卡片滑回

设备状态实时更新
 → 收到 onDeviceStatusChanged 事件 → 更新对应设备卡片的状态/信号/摄像头
 → 在线→离线：设备卡片变灰，"已连接"变为"重连"
 → 离线→在线：设备卡片恢复，显示"连接"

空状态
 → 没有绑定设备时显示引导图
 → "添加设备"按钮跳转到添加设备页
 → "了解硬件类型"跳转到硬件说明页（高端vs低端对比）

#### ③ 交互流程图

用户进入添加设备页（步骤1）
 → 显示两个设备类型卡片
 → 用户选择高端或低端

步骤2：蓝牙扫描
 → 检查蓝牙权限和状态
 → 蓝牙未开启 → 弹窗提示跳转系统设置
 → 开始蓝牙扫描（30秒超时），过滤DartVio设备广播
 → 扫描到的设备实时显示在列表中（名称/MAC/信号强度）
 → 用户点击"连接"选择要配网的设备
 → 未发现设备 → 显示帮助清单+重新扫描

步骤3：配置WiFi（高端设备）
 → 通过蓝牙连接到设备
 → 显示WiFi配置表单
 → WiFi名称默认填充当前手机连接的SSID（可选择其他）
 → 提示"仅支持2.4GHz WiFi"
 → 用户输入WiFi密码 → 点击"配置并连接"
 → 通过蓝牙将WiFi凭证发送给设备
 → 设备连接WiFi → 获取IP地址 → 连接云端（通过手机网关）
 → 配置成功 → 进入步骤4
 → 配置失败 → Toast错误原因（密码错误/路由器不支持/设备离线），允许重试

低端设备额外步骤：PIN验证
 → 配置WiFi成功后，要求输入设备底部标签上的8位PIN码
 → 验证通过 → 绑定设备
 → 验证失败 → 提示"PIN码错误，请检查设备底部标签"

步骤4：绑定完成
 → 设备信息写入本地存储（Device对象）
 → 显示绑定成功页：设备名称/ID/固件版本/WiFi/IP/摄像头状态
 → 用户点击"开始使用" → 跳转设备列表（新设备已在列表中，状态在线）
 → 用户点击"查看设备详情" → 跳转设备详情页

配网中断处理
 → 用户在配网过程中点击返回
 → 确认弹窗"确定退出配网？设备未完成绑定，需重新配网"
 → 确认 → 返回设备列表
 → 取消 → 继续配网

配网超时
 → 任何步骤超过2分钟无响应
 → 提示"配网超时，请检查设备状态后重试"
 → 提供"重新配网"和"返回"选项

#### ③ 交互流程图

对局中硬件状态管理

硬件状态图标（对局页顶部）
 → 实时显示设备连接状态（已连接/连接中/未连接/异常）
 → 点击弹出硬件状态详情弹窗
 → 高端设备显示📷，低端显示📹
 → 颜色：绿色=正常，黄色=连接中/低识别率，红色=异常，灰色=未连接

高端设备自动计分流程
 → 用户投镖 → 硬件摄像头捕捉 → OpenCV识别落点
 → 设备推送 dart_detected 事件（label/score/confidence）
 → 对局页显示"硬件识别中..."→ 识别结果（分区+分数+置信度）
 → 开发阶段：显示"确认"/"修正"按钮，用户确认后提交
 → 量产阶段（自动提交开启）：自动提交，显示5秒撤销按钮
 → 低置信度（<90%）：黄色警告，提示用户确认或手动修正
 → 用户点"修正"：弹出手动输入界面，手动输入正确分数
 → 三镖识别完成 → 推送 turn_complete 事件 → 回合完成

低端设备视频流
 → 连接RTSP流 → H.264解码 → 实时渲染到对局页视频区域
 → 本地比赛：显示自己的靶盘画面
 → 在线对战：轮到谁显示谁的靶盘画面（对手画面通过服务端转发）
 → 视频流不保存不回看
 → 网络差时自动降级分辨率（1080p→720p→480p）
 → 断开时自动重连（最多3次，每次间隔5秒）

硬件状态详情弹窗
 → 点击顶部硬件图标弹出
 → 显示：设备名称/连接状态/延迟/自动计分设置/摄像头状态/识别准确率
 → 可操作：切换自动提交开关/低置信度提示开关/断开连接/查看设备详情
 → 设置修改即时生效，自动保存

自动提交设置
 → 开发阶段默认关闭（每轮需用户确认）
 → 量产阶段默认开启（自动提交+5秒撤销）
 → 可在对局中随时切换（顶部硬件详情弹窗）
 → 也可在全局设置中设置默认值

硬件识别数据与手动计分的统一
 → 硬件识别结果构造为标准 Dart 对象（label/number/multiplier/score/confidence/source=hardware_vision）
 → 与手动/语音输入的数据格式完全一致
 → M2 规则引擎统一处理，不区分输入来源
 ★v1.1：Cricket模式下，仅15-20与Bull为有效分区，其余落点按MISS/无效处理（与M3计分录入一致）
 → 统计时可按 source 筛选（分析硬件识别准确率）
