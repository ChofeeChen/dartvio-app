### 5.1 D1 审计结论（2026-09-27）

结论：**`domain/` 可以整体下沉 `shared`**，没有 Android 依赖。

- ✅ 全目录 **0 处** `import android.*`、`import androidx.*`、`import kotlinx.coroutines.*`
- ⚠️ 仅 **4 个文件** 用到 JVM-only API，需改为 `expect/actual`：

| 文件 | JVM 依赖 | KMP 处理 |
| --- | --- | --- |
| `domain/room/RoomSchedule.kt` | `SimpleDateFormat` / `Calendar` / `Date` / `Locale` / `String.format(Locale)` | `expect` 时间格式化（Android 用 `Calendar`，iOS 用 `NSDateFormatter`） |
| `domain/achievement/PracticeFacts.kt` | `Calendar`（自然日判定） | 同上 |
| `domain/room/OfficialArena.kt` | `Calendar`（官方时间锚点） | 同上 |
| `domain/profile/LocalProfile.kt` | `UUID`（生成 id） | `expect fun randomId(): String`（Android `UUID`，iOS `NSUUID`） |

约束：**不要改用 `java.time`**（minSdk 24/25 未开核心库脱糖会运行期崩溃，见 `RoomSchedule.kt` 注释）；
也不建议直接引 `kotlinx-datetime`（它在 Android 上依赖 `java.time`，会反向逼你开脱糖）。
`expect/actual` 是这里代价最小的做法，且 650 例单测可覆盖现状作回归。

# 8. 密钥与敏感资产怎么处理（Android 侧）

## 8.1 先认清风险等级

| 资产 | 丢了会怎样 | 等级 |
| --- | --- | --- |
| **`keystore/dartvio-beta.jks` + 密码** | **无法再更新任何已安装的应用**（更新必须用同一签名），用户只能卸载重装、本地数据全丢。不可逆转 | 🔴 最高 |
| `keystore.properties` | 只有密码，无 jks 则无害；但两者通常一起备份 | 🟡 随 jks |
| `local.properties`（Supabase URL / anon key、联机后端地址） | anon key 走 RLS 约束，泄露影响可控；可随时轮换 | 🟠 中 |
| `DartVio_邀请码台账_*.txt` | 邀请码被冒用 | 🟠 中 |
| 对外 APK | 无敏感信息，只是体积大 | ⚪ 低 |

**一句话：签名密钥是本项目唯一"丢了就不可逆"的资产，其余都能轮换。**

## 8.2 三层处理（推荐照做）

**① 不入库**（✅ 已完成）
`.gitignore` 已排除 `keystore/`、`keystore.properties`、`*.jks`、`local.properties`、邀请码台账、所有 APK。仓库只留 `.example` 模板，Mac 克隆下来也不含任何秘密。

**② 加密备份 —— 至少 2 份，其中 1 份异地**

```powershell
# 把签名材料打成一个 AES-256 加密包（-mhe=on 连文件名一起加密）
cd "d:/8.Darts/2.0 CodeBuddy Project_DartVio/android"
7z a -p -mhe=on dartvio-signing-backup.7z keystore\dartvio-beta.jks keystore.properties
```

- 密码**不要**写在包旁边或提交进仓库，存进密码管理器。
- 两份副本：① 本机加密盘；② 异地（另一台机器的加密盘 / 私人网盘的加密包 / 银行保管箱级的 U 盘）。
- **不要**放：未加密网盘、邮件正文、聊天记录、仓库任何位置（包括 git 历史里——所以从一开始就别让它进过库）。

**③ 上架前启用「Google Play 应用签名」**（强烈建议，能把 🔴 降级为可恢复）
让 Google 托管真正的签名密钥，你手里的变成 upload key；upload key 丢失可向 Google 申请重置（需身份核验）。
这样「密钥丢失 = 产品死亡」变成「密钥丢失 = 走一次恢复流程」。注意启用后也别放松备份，恢复流程要花时间。

## 8.3 其余资产

- `local.properties`：只留 Windows 本机；Mac 端用模板留空即可（联机与统计会自动关闭，见 `README_DEV.md`）。
- 邀请码台账：不入仓库；要给 Mac 就走加密通道。
- iOS 侧对称处理：证书与私钥只存 Mac，导出 `.p12` 时加密码；`*.mobileprovision` 不入仓库。
- **恢复演练**：每半年或每次换机后，验证一次备份能解开、能用它签出可安装的包。没验证过的备份等于没有备份。
