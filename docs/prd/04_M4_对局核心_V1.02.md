# 1. 模块概述

M4 对局核心模块负责比赛的全生命周期管理：比赛创建、状态机流转、回合提交与校验、撤销处理、局结果与比赛结果判定。v1.3核心修复：状态机补充3条缺失转换；IN规则校验不再返回error（IN不符合是正常比赛行为）；修复AI回合remaining双重扣减Bug；明确AI回合可撤销；战绩归属补充个人投镖数据vs比赛结果二维拆分。

## 1.1 本地比赛定义（v1.2重写）

本地比赛的本质特征是"同一物理镖盘 + 同一台计分设备"，适用于以下两种对手类型：

- • 面对面2人对战：两位玩家在同一场地共用一个镖盘，轮流投镖，在同一台设备上完成计分。
- • vs DartBot AI对战：一位真人玩家与AI对手对战，AI回合由算法自动生成飞镖落点并计分。
本地比赛与在线对战的核心区别：本地比赛为同场地、同设备、单端计分；在线对战为跨场地、跨设备、双端计分 + M5实时同步。

## 1.2 玩家2登录状态处理（面对面2人模式）

本地比赛不强制玩家2登录，以降低线下场景的开局门槛：

| 玩家2状态 | 开局要求 | 战绩归属 | 计分板显示 |
| --- | --- | --- | --- |
| 游客 | 仅需输入昵称 | 仅计入玩家1（已登录方），标注"本地休闲赛" | 玩家2昵称旁灰色"游客"标签 |
| 已登录 | 切换账号或扫码确认身份 | 双方各自计入战绩，标注"本地正式赛" | 正常显示双方头像与昵称 |

游客玩家2的比赛数据：不生成独立玩家统计记录，仅作为玩家1比赛记录中的对手信息保存（昵称+最终分数）。

## 1.3 DartBot AI对战定义（v1.2新增，从M11移入）

| 维度 | 说明 |
| --- | --- |
| 入口位置 | 本地比赛入口下的对手类型选项之一（与"面对面2人"并列） |
| 难度选择 | 4档难度（Easy/Medium/Hard/Pro），每档对应不同PPR范围、结镖率、180率、延迟范围 |
| 交互流程 | 与面对面2人完全一致：选择规则→争红心（AI随机生成落点）→轮流投镖→计分→局结果→比赛结果 |
| AI回合行为 | AI回合自动生成飞镖落点（基于难度配置的概率分布），自动提交计分，可配置AI投镖延迟模拟真人节奏 |

# 4. 回合提交与校验

★V1.00：回合提交的对外入口唯一，由 M4 内部按 match.config.gameType 分发。M3 侧只调用 submitTurn(params)，不得自行判断 gameType 选择函数——避免入口分裂。

| gameType | 提交入口（M3 唯一调用） | M2 校验函数 | 运行时字段 / 胜负判定 |
| --- | --- | --- | --- |
| x01 | submitTurn(params)→X01 分支 | RuleEngine.validateTurn() | player.remaining；先合法结镖者胜（IN/OUT规则按配置） |
| cricket | submitTurn(params)→submitTurnCricket(params) | RuleEngine.validateCricketTurn() | player.cricketState；关闭全分区且得分≥对手 |

同一场比赛 gameType 固定不变；两个分支共用 §2 主状态机，但回合校验、回合数据字段、胜负判定各自独立。

## 4.2 提交流程伪代码

function submitTurn(params):
 match = getMatch(params.matchId)

 // ★V1.00：对外唯一入口，按 gameType 内部分发（禁止 M3 自行选择函数）
 if match.config.gameType == "cricket":
 return submitTurnCricket(params)
 // ---- 以下为 X01 分支 ----

 if match.state != "in_progress":
 return error("比赛不在进行中") // 阻断性：M3 必须 Toast

 player = match.getCurrentPlayer()
 if player.id != params.playerId:
 return error("非当前选手") // 阻断性：M3 必须 Toast

 // 1. 校验回合总分
 expectedScore = sum(d.score for d in params.darts)
 if expectedScore != params.turnScore:
 return error("回合总分与镖分之和不一致") // 阻断性：M3 必须 Toast

 // 2. 调用M2规则引擎校验（★M2 是唯一规则来源）
 validation = RuleEngine.validateTurn(
 remainingBefore = player.remaining,
 darts = params.darts,
 turnScore = params.turnScore,
 inRule = match.config.inRule,
 outRule = match.config.outRule,
 isFirstDartOfLeg = (player.dartCountInLeg == 0),
 inputMode = params.inputMode,
 isCheckoutConfirmed = params.isCheckoutConfirmed // ★V1.00修复：原误写为 params.isCheckout，导致M2收到的确认标志恒为false，快速总分模式永远判Bust（P0-1 修复因此从未生效）
 checkoutDartCount = params.checkoutDartCount // ★V1.00新增：结镖镖数必须透传，否则M2走「兼容旧调用」分支跳过可达性校验（v1.7 修复被绕过）
 )
 if validation.error != null:
 return error(validation.error) // 阻断性：M3 必须 Toast

 // ★V1.00修复：Bust / Checkout 一律以 M2 返回的 validation 为准，
 // 不再与 params.isBust / params.isCheckout 比对——那是双来源冲突，
 // 会把「M3 算错」升级成阻断性提交失败。M3 的同名入参仅用于本地即时反馈。

 // 3. IN规则处理（★v1.3修正：不返回error，★v1.6补充快速总分说明）
 // IN规则不符合是正常比赛行为：第一镖未命中双倍/三倍区时该镖score=0，
 // 选手继续投剩余镖，整回合正常提交。例如Double In第一镖S20(0分)+T20+T20=120分，
 // 这是合法回合，不应拒绝提交。M2已将不符合IN规则的镖score设为0。
 // ★v1.6：快速总分模式(inputMode=quick_total)下M2跳过IN规则逐镖校验，
 // validation.inRulePassed恒为true，IN规则合法性由M3输入层非法分数过滤保证
 // （Double In 17个/Master In 9个，详见M3 §5.2），此分支在快速总分模式下不触发。
 if not validation.inRulePassed:
 // ★V1.00：此处原为 params.turnScore = validation.adjustedScore（改写入参），已移除。
 // 回合总分一律取 validation.adjustedScore / turn.turnScore，不再回写入参。

 // 4. 记录回合数据（★v1.5 P0-2修复：使用validation.adjustedDarts而非params.darts，
 // 确保IN规则不符合的镖score已改为0，darts数组sum==turnScore，M9 PPR统计正确）
 turn = Turn(
 playerId = params.playerId,
 darts = validation.adjustedDarts, // ★v1.5：必须使用调整后的镖数组
 turnScore = 0 if validation.isBust else validation.adjustedScore, // ★V1.00：以M2判定为准
 isBust = validation.isBust, // ★V1.00：以M2判定为准
 isCheckout = validation.isCheckout, // ★V1.00：以M2判定为准
 checkoutDarts = params.checkoutDarts if validation.isCheckout else null,
 inputMode = params.inputMode,
 inputSource = params.inputSource, // 透传inputSource（ai_generated/hardware_vision等）
 turnIndex = params.turnIndex ?? match.currentRound // ★V1.01新增：AI 回合不传 turnIndex，兜底取当前回合序号（否则 Turn.turnIndex 为空，M9 统计错）
 )
 match.addTurn(turn)

 // 5. ★V1.00核心修复：以下「扣分 + 切换」是X01的必经逻辑，禁止省略或提前return。
 player.previousRemaining = player.remaining // ★v1.6：保存前回合剩余分
 if validation.isBust:
 player.remaining = player.previousRemaining // Bust：不扣分
 else:
 player.remaining = player.previousRemaining - turn.turnScore
 // ★V1.00修复：扣减量必须取M2判定值 turn.turnScore，禁止用 params.turnScore
 // 不变量（M7得分三件套据此显示）：
 // player.previousRemaining - turn.turnScore == player.remaining

 // 6. 判定局/比赛结果
 if validation.isCheckout:
 player.legsWon += 1
 // ★v1.5：休闲模式legsToWin=0时，单局结束直接leg_finished，不检查整场胜利
 if match.config.legsToWin > 0 and player.legsWon >= match.config.legsToWin:
 match.state = "finished"
 match.sub_status = "match_finished"
 match.winner = player.id
 else:
 match.state = "finished"
 match.sub_status = "leg_finished" // 休闲模式单局结束，局结果页显示"再来一局/退出"
 // ★V1.00：Checkout 时不切换选手、roundsPlayed 不+1（本局随即结束）
 else:
 match.switchCurrentPlayer() // ★V1.00：非Checkout必须切换选手
 match.roundsPlayed += 1 // ★v1.4：记录已完成回合数
 match.currentRound += 1

 // ★v1.4新增：检查是否达到最大回合数（超轮判定）
 if match.currentRound > match.config.maxRounds:
 match.overtimeTriggered = true
 overtimeResult = M2.overtimeJudge(
 remaining1 = match.players[0].remaining,
 remaining2 = match.players[1].remaining,
 totalScore1 = match.players[0].totalScore,
 totalScore2 = match.players[1].totalScore,
 overtimeRule = match.config.overtimeRule
 )
 if overtimeResult.winner > 0:
 // min_score方式直接判定胜者
 winner = match.players[overtimeResult.winner - 1]
 loser = match.players[overtimeResult.winner == 1 ? 1 : 0]
 winner.legsWon += 1
 match.overtimeWinner = overtimeResult.winner
 // ★v1.5：生成超轮说明文本，供M7局结果页显示
 match.overtimeReason = f"本局达到{match.config.maxRounds}回合上限，按最小分值判定——{winner.nickname}剩余{winner.remaining} < {loser.nickname}剩余{loser.remaining}，{winner.nickname}胜"
 // ★v1.5：休闲模式legsToWin=0时直接leg_finished
 if match.config.legsToWin > 0 and winner.legsWon >= match.config.legsToWin:
 match.state = "finished"; match.sub_status = "match_finished"
 match.winner = winner.id
 else:
 match.state = "finished"; match.sub_status = "leg_finished"
 else:
 // diddle方式或min_score极端平局 → 进入超轮争红心
 match.overtimeReason = f"本局达到{match.config.maxRounds}回合上限，争红心决胜"
 match.state = "sudden_death"
 else:
 // 未达最大回合数，正常继续
 // 检查是否AI回合
 if match.getCurrentPlayer().isAI:
 match.sub_status = "ai_turn"
 triggerAITurn(match)
 // ★V1.01：triggerAITurn 内部含 await sleep，为异步调用，此处不阻塞等待。
 // AI 回合的提交经其内部 submitTurn 递归回到本函数完成结算。AI 回合期间 match.sub_status == "ai_turn"，M3 必须屏蔽人类输入。

 // 7. 在线对战：通过M5同步
 if match.type == "online":
 M5.broadcastTurnSubmitted(match.id, turn)

 return success(turn)

**★V1.00新增：校验失败分类与前端反馈规范（submitTurn 返回语义）**

| 类别 | 典型场景 | M4 返回 | M3/前端要求 |
| --- | --- | --- | --- |
| 阻断性失败 | 参数缺失或非法（如 isCheckoutConfirmed 未传）、match.state≠in_progress、非当前选手、M3 与 M2 的 Bust/Checkout 判定不一致 | return error("具体原因")，不写库、不切换选手 | ★必须以 Toast 提示具体原因，禁止静默失败；不刷新剩余分 |

## 4.3 快速总分模式Checkout处理（v1.2新增）

快速总分模式下，系统无法确定最后一镖是否双倍。M3在用户点"下一选手"时弹出Checkout确认弹窗（详见M3 §5.2），用户选择后将结果传入M4：

| 用户选择 | M4处理 | 数据记录 |
| --- | --- | --- |
| 1镖/2镖/3镖 | 判定为合法Checkout，结束本局/整场 | isCheckout=true, checkoutDarts=选中值, darts第1条=总分+2条MISS |
| 爆镖 | 判定为Bust，回合0分，剩余分不变，切换选手 | isBust=true, turnScore=0, darts全部MISS |
| 取消 | 不提交，回到输入状态 | 无变化 |

Single Out模式：输入总分==剩余分时直接判定Checkout，不弹窗（无双倍歧义）。

# 5. 撤销机制（v1.2重构：逐镖回退）

## 5.1 撤销类型

| 场景 | 触发方式 | 行为 | 锁定机制 |
| --- | --- | --- | --- |
| 本地比赛-未提交 | M3组件内点撤销 | 逐镖回退：回退最后一镖，镖位原值灰色显示，直接输入新值 | 无锁定（本地单端） |
| 本地比赛-已提交 | 对局页点撤销（切换选手后5秒内） | 回退到上一选手，显示其darts，可继续逐镖回退修改 | 5秒窗口 |
| 在线对战-未提交 | M3组件内点撤销 | 逐镖回退（同本地） | 无锁定 |
| 在线对战-已提交 | 对局页点撤销 | 5秒撤销窗口 + 对手开始操作即锁定。回退到上一选手，可逐镖回退修改 | 5秒窗口 + 对手操作锁定 |

## 5.3 在线对战撤回锁定时序

选手A提交回合 (t=0)
 → M5广播 turn_submitted
 → 选手B收到，显示A的回合结果
 → 撤销窗口开始（5秒）

t=0~5s：选手A可点撤销
 → A点撤销 → M5发送 turn_undo_request
 → B端收到 → 锁定B的输入（禁止操作）
 → B端显示"对手正在撤销"
 → A端回退，修改后重新提交
 → M5广播 turn_resubmitted
 → B端解锁

t>5s 或 B开始操作：
 → 撤销锁定，A不可撤销
 → M5广播 undo_locked (原因: 窗口过期/对手已操作)

## 6.4 Cricket 胜负判定与局结果流转

获胜条件（同时满足，M2 §4.4）：①本方已关闭全部7个分区；②本方总分≥对手总分。

• 单局模式(matchMode=casual)：本月局结束即 leg_finished，局结果页显示"再来一局/退出"，本局有胜负归属；

• 多局模式(matchMode=multi)：一方累计legsWon达到legsToWin时 match_finished，否则 leg_finished 进入下一局（先手轮换）；

• 双方均关闭全部分区且分数相同：继续比赛直到一方得分领先（无maxRounds限制）。

★V1.02 变体化胜负判定（不再硬编码「≥」）：
　• 判定链：本方已关闭全部 7 分区 → 按 cricketVariant 的 WinCompare 与对手分比较；
　　- standard（GE）：本方分 ≥ 对手分 → leg_finished，本方胜；
　　- cut_throat（LE）：本方分 ≤ 对手分 → leg_finished，本方胜（分数相同视为达成）；
　　- no_score（NONE）：关闭全部 7 分区即胜，不读取任何分数；
　• 判定结果由 M2 返回的 isGameOver / winner 提供，M4 不得另写一套比较逻辑；
　• 局结果流转（casual → leg_finished / multi → 累计至 legsToWin）不因变体而改变。

## 6.6 Cricket 下 DartBot AI 回合策略

DartBot在Cricket模式下的策略与X01不同，核心是"关闭优先、得分次之"：

• 目标选择：优先瞄准"本方未关闭"的分区（按20→19→18→17→16→15→Bull优先级）；若某分区本方已关闭但对手未关闭，则瞄准该分区得分（20最高优先）；若双方均已关闭该分区（死区）则跳过；

• 命中率：由aiPpr换算为单镖命中目标分区的概率，并按§7.1.1自适应规则调整；

• 关闭阈值感知：当某分区本方计数=2时，优先补1次计数完成关闭；

• Bull处理：Bull需累计3次计数关闭（Outer=1/Bull=2）；AI在需要关闭Bull时优先瞄准Bull；

• 无Bust概念：Cricket回合不会被判Bust，回合结束一律切换选手。

★V1.02 AI 策略按变体分派：
　• standard：维持现有策略（关闭优先 → 打对手未关闭的高分区得分）；
　• no_score：仅「关闭优先」，不做任何得分目标选择；
　• cut_throat：仅「关闭优先」；本方全关后仍瞄准对手未关闭的最高分区（该镖不得分，等同不加分）；
　• ⛔ 明确不做「故意送分 / 主动避分」的负向策略 —— 避免 AI 行为不可解释、被玩家误判为缺陷；
　• ★缺陷修复：AI 目标选择的兜底值不得硬编码 20（随机 / 变体目标集下 20 可能非法），
　　必须从当前有效目标集内取值（如取目标集内最大的非 Bull 分区）。

# 7. DartBot AI回合逻辑（v1.2新增，★v1.8自适应难度）

## 7.1 AI难度配置

| 难度 | PPR范围 | 结镖率 | 180率 | 投镖延迟 | 适用场景 |
| --- | --- | --- | --- | --- | --- |
| 入门(Easy) | 25-40（中值32） | 15% | 2% | 1.5-2.5s | 新手入门，★v1.4默认 |
| 进阶(Medium) | 40-55（中值47） | 30% | 5% | 1.0-2.0s | 休闲玩家 |
| 高手(Hard) | 55-70（中值62） | 50% | 10% | 0.8-1.5s | 进阶玩家 |
| 专业(Pro) | 70-90（中值80） | 70% | 20% | 0.5-1.0s | 高手挑战 |

★ v1.4调整：PPR范围从30-100调整为25-90。PPR 25是绝对新手水平（每镖约8.3分），PPR 90是职业选手水平（每镖30分），PPR 100在真实比赛中几乎不可能达到。P0使用四档中值作为aiPpr（入门32/进阶47/高手62/专业80），P1增加PPR滑块连续可调（25-90步长1）。aiPpr字段存储具体PPR值，AI行为参数基于ppr动态计算。

7.1.1 同级自适应难度（★v1.8新增，AI难度以本表为唯一来源）

为提升真人玩家粘性，DartBot在所选难度档位的PPR区间内，随对手实时表现"遇强则强、遇弱则弱"：

① 基准：以所选档位PPR中值为基准值(basePpr)，区间上下限为该档位PPR范围（如进阶40-55，basePpr=47）；

② 采样：每完成1个回合，计算真人玩家滚动最近N=5回合的实际PPR(playerPpr，=该窗口内真人总得分/总镖数×3，仅统计真人回合)；

③ 调整：targetPpr = clamp( basePpr + k×(playerPpr - basePpr), lower, upper )，k为跟随系数(建议0.5，P1可配)；

④ 平滑：aiPpr = round( 0.7×aiPpr_prev + 0.3×targetPpr )，避免AI表现突变；

⑤ 上下限：aiPpr始终限制在该难度档位PPR范围内，防止跨档失衡；

⑥ 档位边界：入门档不允许自适应到进阶区间，专业档不因对手孱弱而跌出专业下限；

⑦ 关闭开关：matchMode=casual或用户关闭"智能难度"时，aiPpr恒为档位中值。

★ 数据来源：playerPpr由M9统计口径（真实投镖，input_source≠ai_generated）提供，AI回合不计入。

★ 本规则为AI难度唯一来源；M11中的DartBot难度表已废弃（见M11 v1.2变更记录）。
