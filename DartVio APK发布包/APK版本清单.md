# DartVio APK 版本清单

> 每个 APK 一个版本、一个文件名、一行台账。**版本号的唯一真源是 `app/build.gradle.kts` 里的
> `versionCode` / `versionName`**，文件名与包内显示的版本都从它派生。

## 一、版本号规则

| 项 | 规则 | 理由 |
| --- | --- | --- |
| `versionCode` | 整数，**每次发版 +1，只增不减** | Android 靠它判定新旧；不递增，朋友手上的旧版无法覆盖安装 |
| `versionName` | `0.1.<versionCode>`（当前 `0.1.18`） | 末位与 versionCode 对齐 ⇒ 包内显示、遥测 `app_version`、APK 文件名三者永远一致，收到「某版本的反馈」能立刻定位构建 |
| 版本号唯一出处 | `app/build.gradle.kts` 顶部的 `appVersionCode` / `appVersionName` 两个 val（2026-09-26 起） | 先前包内版本、文件名、台账三处各写一遍；三者不一致时，用户报上来的版本号就没有意义了 |
| beta 后缀 | `versionNameSuffix = "-beta-demo"` ⇒ 包内显示 `0.1.3-beta-demo` | 由构建变体自动附加，不手改 |
| 文件名 | `DartVio_BetaDemo_v{versionName不含后缀}_{特性}_{YYYYMMDD}.apk` | 版本 + 特性 + 日期，目录里按名排序即可看出时间线 |
| `latest` 副本 | `DartVio_BetaDemo_latest.apk` = 最新归档的字节级副本 | 装真机时不用挑文件名；**不单独算一个版本** |

## 二、发版 SOP（每次出包照做）

1. `app/build.gradle.kts`：`versionCode` +1、`versionName` 末位同步，注释里写清本次变更。
   **若本版采纳了体验者的意见**，顺手往 `data/beta/BetaFeedback.kt` 的 `BetaFeedbackAck.items`
   顶部加一条（写来源、日期、落地版本）—— 它是「我的 → 我的反馈」页右边那个数字的真源，
   只有在这里登记了，提意见的人才看得到闭环。
2. 构建并自测（PowerShell，先设 JAVA_HOME）：
   ```
   $env:JAVA_HOME="C:\Program Files\Android\Android Studio\jbr"
   .\gradlew.bat assembleBeta testDebugUnitTest --console=plain
   ```
   产物：`app/build/outputs/apk/beta/app-beta.apk`（约 15 MB）。
3. 复制到本目录并按上面的文件名规则重命名；核对包内版本：
   ```
   aapt2 dump badging <apk> | findstr versionCode
   ```
4. 在本文件「版本台账」表格**置顶插入**一行，填：版本 / 日期 / 变更 / 体积 / SHA256 / 验证状态。

变体约定：**对外试用一律 `assembleBeta`**（真 keystore 签名、`isDebuggable=false`、入口全开、默认上报匿名统计）。
`debug` 包仅本机联调用，不进对外分发；`release` 变体尚未启用。
