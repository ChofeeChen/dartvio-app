# DartVio Beta 体验反馈 · 填写模板

目的：让每一条反馈**不用二次加工**就能汇总成表，直接进优化清单。
所以下面这份模板刻意做成「字段 + 枚举值」，而不是开放式的「请说说你的感受」。

---

## 一、收集方式（推荐组合，成本从低到高）

| 方式 | 适合 | 做法 | 代价 |
| --- | --- | --- | --- |
| **群内接龙（推荐起步）** | 20–50 人小范围内测 | 把第二节的代码块发群里，让大家复制后填，直接在群里回帖 | 人工抄进表，20 人以内可接受 |
| 腾讯文档 / 飞书表格（强烈推荐） | 同一规模，但想省掉抄录 | 表格列 = 下面第三节的 CSV 表头，填表人一行一条 | 需填表人会打字用表；出表即可直接给我 |
| App 内「反馈」入口（二期） | 人数上到百人级 | 页面内填完直接带上 `体验ID / 版本号 / 机型` 落库 | 要开发；**不建议为 20 人做** |

**不建议**：语音、截图配一句「这里不好」、开放式长文 —— 这三类信息量大但不可汇总，
最后只能一条条人工读，20 人就到上限了。

---

## 二、复制区（体验者直接复制填写）

```
【DartVio 反馈】
体验ID：(在「我的」页底部可看到，形如 a1b2c3d4)
版本号：
机型系统：
日期：

1. 发生位置：            （首页 / 大厅 / 创建比赛 / 房间等候 / 对战 / 精准工坊 / 数据 / 我的）
2. 类型：                （bug / 看不懂 / 不顺手 / 想要的功能）
3. 严重程度：            （阻断 / 影响体验 / 无所谓）   ← 阻断 = 这件事做不下去了
4. 我原本想做的事：
5. 实际发生了：
6. 期望是：
7. 能否复现：            （每次 / 偶尔 / 只出现一次）
8. 截图或录屏：          （有 / 无）
```

规则（写进群里，能省掉一半来回问）：
- **一条反馈只说一件事**：两件事混在一条里，最后一定会被当成一件处理掉。
- 「看不懂」和「不好用」要分开：`看不懂` 是信息设计问题，`不好用` 是流程问题，改法不同。
- 严重程度只选一个，且**只对自己**判断：你觉得无所谓就填无所谓，不用替别人升级。

---

## 三、汇总表表头（我来整合时用的列，可直接建成表格/CSV）

```
反馈ID,体验ID,版本号,机型,日期,位置,类型,严重程度,想做的事,实际发生,期望,能否复现,有截图,处理状态,归属模块
```

- `归属模块` / `处理状态`（待定 / 已排期 / 已修 / 不做）是我这边补的两列，体验者不用填。
- `不做` 也要留着：beta 期「明确不做」的信息和「要改」一样重要，否则同一个建议会被提十次。

---

## 四、每轮收尾的三个固定问题（单独发，不要混进日常反馈）

1. **这周你主动打开了几次？为什么打开？**（不看次数看动机：是「想打一局」还是「想看数据」）
2. **有没有哪一次你想用它、结果发现用不了，于是放下了？**（这一条专门捞流失点）
3. **如果只能改一个地方，你希望是哪一处？**（强制排序，避免清单发散）

---

## 五、合规底线（收集反馈时同步做到）

- 只收集上述字段，**不收集手机号、通讯录、通讯内容**；`体验ID` 是随机编号，不绑定自然人。
- 反馈内容里如果出现截图，发群里前提醒自行裁掉含个人信息（昵称、头像、微信名）的部分。
- 明确一句「可随时退出、退出即停止收集」，并在群里置顶留存。
