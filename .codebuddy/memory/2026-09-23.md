## 联机 bug（真机双机）：房主端看不到已加入的客人
- 现象：A 建房（6 位房间号，走**在线/Supabase** 而非 LAN——LAN 分支填的是 IP）→ B 用房间号加入并准备；**B 端看得到 A+B，A 端只有自己、仍提示"等待玩家加入"**。
- 架构要点（事件溯源）：状态 = `RoomEventReplay.replay(events)`，写入 = 往 `dartvio_room_events` 插一行（`unique(room_id,seq)`）；`RoomRepositoryProvider` 切源；UI `RoomWaitingScreen` 读 `repo.observeRoom(roomId)`。
- **病理解释**：B 加入时 `ensureStream→refreshEvents` **拉了全量历史**（含 A 的 ROOM_CREATED）⇒ 看得到两人；A 端本地已有自己的事件，之后的变化**只能靠 Realtime 推送** ⇒ 推送不来就永远停在 1 人。
- 根因判断（高置信）：事件表没进 `supabase_realtime` publication，或 RLS 拦住 anon 的 SELECT。**这类失败完全静默**：WS 照样 join、状态照样 LIVE，但一条都不推。项目里**没有建表 .sql**（表是控制台手建的），无法从代码自证。
- 已改（编译 + 单测均通过）：
  - `OnlineRoomApi.fetchEvents(roomId, afterSeq = 0)` 支持增量（`&seq=gt.N`）；
  - `OnlineRoomRepository.refreshEvents` 只拉本机最大 seq 之后的部分；
  - `ensureStream` 的泵里并行一条 **3 秒轮询兜底**（`POLL_INTERVAL_MS`），Realtime 降级为"加速器"而非"必需品"。
  - 坑：Kotlin 里 `while (isActive)` 需 `import kotlinx.coroutines.isActive`（编译报错一次才补上）。
- ★环境：本机 gradle 无 JAVA_HOME，须 `$env:JAVA_HOME="C:\Program Files\Android\Android Studio\jbr"`（Android Studio 自带 jbr）才能构建。
- ★★★**根因实锤 + 修复（更正上一条判断）**：Supabase 控制台截图证实 publication 含 events 表、RLS anon SELECT 放行 ⇒ 假设排除。写 Python `websockets` 探针直连 Realtime（与 App 同款 join 报文）+ POST 测试事件：**join ok、system "Subscribed to PostgreSQL"、推送 0.1s 到达 —— 但事件名是 `postgres_changes`（行在 `payload.data.record`、类型 `payload.data.type`），而 App 的 `parse()` 只认老格式 `event="insert"`+`payload.record`** ⇒ App 收到每条推送都在解析时静默丢弃。这解释一切：客人拉全量所以正常，房主只靠推送所以永远等不到。首次探针 20s 没收到是 WAL 管道冷启动（>20s），之后 0.1s 级。
- 修复：`RoomEventStream.parse` + `RoomStateStream.parse` 兼容两种格式（新 `postgres_changes` 为主、老 `insert` 保留）；编译 + 全量单测通过（773 例基线）。轮询兜底保留。
